# ADR-012: 段階1の方針決定（段階0.5の採用とFOLLOWUPS混入欠陥の修正）

- 日付：2026-08-27
- 状態：草案（ユーザ承認前）

## 背景

ADR-011（`docs/decisions/ADR-011-review-loop-design.md`）決定8は、段階0
（毎ラウンド人間が1キーで承認）の実測を見てから段階1（指示文の生成を
ループに取り込む）以降の要否を決めるとしている。

段階0の初回試走（`docs/ai_loop_state/review_loop_trial_2026-08-26.md`）は
1ラウンドで人間が`q`を選んで終了し、機構の通過判定8項目すべて○だった。
その後、段階1の2案（案A：起案役の新設、案C：監査役のCONTRADICTIONS節を
そのまま次ラウンドのinstructionにする）を比較するための材料を実測し、
`docs/ai_loop_state/stage1_options_2026-08-27.md`に記録した。この過程で、
`scripts/review_loop.sh`の`c`選択時の実装に、監査役のFOLLOWUPS節が次
ラウンドのinstructionに混入する欠陥があることも判明し、`ERRORS.md`
「`review_loop.sh`: 次ラウンドのinstructionに監査役のFOLLOWUPSが混入する」
に記録した。

本ADRは、これらの実測に基づいて段階1の方針を決定する。

## 決定

1. **案Cを採用しない。**
2. **段階1として「段階0.5」を採用する。** 定義: `VERDICT`が`REVISE`のとき
   のみ自動で次ラウンドへ進み、`APPROVE_CONTINUE`のときは人間が次の
   instructionを書く。`HALT_NEEDS_HUMAN`／`DONE`は従来どおり人間のみ
   （`review_loop.sh`は既にこの2値では`c`を選べない設計になっている）。
3. **FOLLOWUPS混入欠陥を先に修正する（決定2の前提条件）。**
4. **段階2（案A）へ進む条件を数値で書く。** 段階0.5でのREVISE自動継続が
   累計10ラウンド分（複数セッションにまたがってよい）蓄積された時点で、
   案Aへの移行を再検討する。**この10という値に根拠は無く、暫定値である。
   実測が溜まった時点で見直す。**

**段階0.5自体の自動化ロジック（REVISE時に人間の入力を待たず次ラウンドへ
進む部分）の実装は、本ADRの決定事項ではあるが、実装そのものは別タスクと
する。** 本ADRに伴って今回実装するのは決定3（FOLLOWUPS混入欠陥の修正）
のみであり、`review_loop.sh`の`c`選択（人間による1キー承認）という段階0の
骨格自体は変更しない。

## 各決定の根拠

**決定1（案Cを採用しない）**: `stage1_options_2026-08-27.md`の実測に
基づく。少なくとも次の2点が根拠になる。

- 初回試走のreview.mdからCONTRADICTIONS節を機械的に抽出したところ
  （`awk '/^CONTRADICTIONS:/{flag=1; next} /^FOLLOWUPS:/{flag=0} flag'
  review.md`）、10行・1375バイトの出力が得られたが、その内容は
  「- なし」に続けて監査役が"なぜ矛盾が無いと判断したか"を説明する
  文章であり、**実行役への具体的な行動指示として成立していなかった**
  （同文書「3. この抽出結果は次ラウンドのinstructionとして成立するか」）
- 監査役は`scripts/review_audit_prompt.md`の出力形式指定に無い
  「検証した根拠（矛盾なしの裏付け）」という見出しを**自発的に追加して
  いた**。案Cは機械的な節抽出に全面依存する設計だが、監査役が仕様どおり
  の節構成を厳密に守らない場合、この前提が崩れる（同文書「2.」の
  「重要な観測」）

**これは`APPROVE_CONTINUE`固有の問題ではない。** CONTRADICTIONS節は
仕様上「報告書と成果物の間の事実の矛盾のみを箇条書きにする」ものであり、
構造的に**「何が誤りか」を述べる節であって「次に何をすべきか」を述べる
節ではない**。REVISE時（矛盾が実際にある場合）でも、CONTRADICTIONSの
各項目は指摘であって作業指示ではないという性質は変わらない。ただし、
REVISE時に実際にどう機能するかは今回のデータ（`APPROVE_CONTINUE`1件
のみ）からは判定できておらず、「未決定・限界」節で改めて明示する。

**決定2（段階0.5の採用、案Aを今回採らない理由）**: 案Aのコスト見積り
（`stage1_options_2026-08-27.md`「5.」、約0.225ドル増・約42%増）は、
「起案役はopus・5ターン」「コストはターン数に比例する」という**2つの
未検証の仮定に依存する**。後者の仮定は、`docs/ai_loop_state/
audit_experiment_2026-08-26.md`の過去の実測（同じ`--model opus`・同じ
`num_turns=1`でも`total_cost_usd`が0.0465〜0.1210ドルの幅でばらついた）
と矛盾する。したがって**このコスト見積りを決定の主根拠にはしない**。

主根拠は、**案Aは新しいプロセス（起案役）と新しい権限プロファイルを
増やすが、段階0の実測はまだ1ラウンド1セッション分しかない**ことである。
`docs/ai_loop_state/2026-08-26.md`「§3-A」が記録したとおり、
`work_loop.sh`は計画書のサンプルを大きく超える完成度で作り込まれながら
実運用1件で停止した前例があり、作り込みの精度と実運用での安定性は別の
問題である。実測が1ラウンド分しかない段階で新しいプロセス・新しい権限
プロファイルを増やすことは、この前例と同型のリスクを負う。段階0.5は
新しいプロセスを増やさず、既存の監査役の判定（VERDICT）だけを使って
自動化の範囲を限定的に広げる、より小さな一歩である。

**決定3（FOLLOWUPS混入欠陥を先に修正する）**: `ERRORS.md`「`review_loop.sh`:
次ラウンドのinstructionに監査役のFOLLOWUPSが混入する」が記録すると
おり、現在の実装（`c`選択時）は`CURRENT_INSTRUCTION_FILE`に
`review.md`**全体**（VERDICT行・CONTRADICTIONS節・FOLLOWUPS節）を代入
している。段階0.5はREVISE時に人間の入力を待たず自動継続する設計であり、
このとき次ラウンドのinstructionにFOLLOWUPS（品質改善提案であって矛盾の
指摘ではない）が混じったままだと、自動継続のたびに不適切な指示が
実行役へ渡り続ける。したがって、段階0.5を実装する前に、次ラウンドの
instructionから最低限FOLLOWUPS節を除く修正が前提条件になる。

**実装方針**: 次ラウンドのinstructionは、`review.md`から**FOLLOWUPS節
より前（VERDICT行＋CONTRADICTIONS節）を機械的に除去した内容**とする
（`awk '/^FOLLOWUPS:/{exit} {print}' review.md`相当）。CONTRADICTIONS
節**だけ**を渡す案C（決定1で却下）とは異なり、VERDICT行を含めた
`review.md`の大部分をそのまま残す最小限の修正とした。決定1が指摘した
「CONTRADICTIONSは単独では行動指示として機能しない」という性質への
本格的な対処（例えば、元のinstructionとCONTRADICTIONSを組み合わせて
指示性を補う設計）は、**決定2（段階0.5）の自動化ロジック自体を実装する
別タスクの中で、実測を踏まえて設計する方が適切**と判断し、本ADRの実装
スコープには含めない。今回は`ERRORS.md`に記録した具体的な欠陥
（FOLLOWUPSの混入）の解消のみを最小スコープで行う。

**決定4（段階2へ進む条件）**: 決定2の段階0.5自体が「未測定の上に立って
いる」（次節参照）ため、段階2（案A）の要否を判断するには、段階0.5の
実測を一定量蓄積する必要がある。10ラウンドという数値に統計的・実測的な
根拠は無く、暫定値である。少なくとも1桁の実測（1〜数ラウンド）では
「たまたま機能した／しなかった」を判別できないという直感に基づく仮の
基準であり、実測が溜まった時点で見直す。

## 却下した案

### 案C（監査役のCONTRADICTIONS節をそのまま次ラウンドのinstructionにする）

決定1・その根拠を参照。CONTRADICTIONS節の機械的抽出が、今回の実測では
行動指示として成立せず、監査役が出力形式指定を厳密に守らないことも
あるため、機械的な節抽出への全面依存はリスクが高いと判断した。

### 案A（起案役の新設）を今回は採らない

決定2・その根拠を参照。新しいプロセス・新しい権限プロファイルを増やす
判断を、段階0の実測（1ラウンド1セッション）だけで行うのは早計と判断
した。「今回は」という留保のとおり、決定4の条件を満たした時点で再検討
する。

## 未決定として明示する事項

- **`REVISE`時にCONTRADICTIONSが次のinstructionとしてどう機能するかは
  未測定である。** 初回試走は`APPROVE_CONTINUE`1件のみであり、
  **決定2（段階0.5）はこの未測定の上に立っている。** 段階0.5の自動化
  ロジックを実装した後、REVISE自動継続が実際に意味のある次ラウンドを
  生むかどうかは、実装後の試走で確認する必要がある
- 停止条件3種（ラウンド数上限／同一VERDICTが2ラウンド連続／no-opハッシュ
  不変）・exit 2（実行役の呼び出し失敗）・exit 13（監査役の呼び出しが
  成立しなかった場合）の経路は、ADR-011の時点から引き続き未検証である
- `~/comic_checker-agent-notes/audit_experiment/writeonly_probe_result.json`
  の`permission_denials`について、明示的なdeny一致による拒否か、
  `--allowedTools`未指定による既定拒否かは判別できていない（未解明の
  まま記録している。`docs/ai_loop_state/audit_experiment_2026-08-26.md`
  「追記（2026-08-27）」参照）
- 段階0.5の自動化ロジック（REVISE時に人間の入力を待たず次ラウンドへ
  進む部分）自体の実装は、本ADRでは行わない
