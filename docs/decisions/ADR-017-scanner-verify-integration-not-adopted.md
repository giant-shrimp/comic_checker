# ADR-017: 個人情報走査の CLI を verify.sh のゲートに組み込まない

- 日付：2026-09-05
- 状態：採用

## 背景

走査器（`scripts/check_no_personal_info.py`、Issue #251）の新設後、これを
`scripts/verify.sh` の常時実行ゲートに組み込めるかを検討した。組み込めれば、
CLAUDE.md の作業ルール「リポジトリ内のあらゆるファイルに個人名を記載しない」
を機械的に検査し続けられる。

## 測定

- 追跡対象22ファイルで合計145件のヒット
- 実際に除去すべき個人情報は0件（全件が誤検出）
- 誤検出の主因は、本プロジェクトが扱う題材の名称が人物の敬称と同じ末尾を持つこと
- 各数値の導出コマンドは Issue #256 のコメントに記載

## 決定

1. **個人情報走査の CLI を `verify.sh` のゲートに組み込まない。**
2. **起票・PR作成の前に人間が手動で実行する補助ツールとして位置づける。**
   対象は「これから外部に出す文書」（Issue・PR・コメントの下書き等）に限定する。

## 検討した案と棄却理由

- **検出パターンの絞り込み**: 棄却。誤検出を大幅に減らせる境界条件は存在するが、
  同じ条件が実在人名の典型形（2文字以上の名前の2文字目に敬称が続く形）も
  同時に除去してしまう。誤検出と検出漏れがパターン側では分離できない。
- **走査範囲を変更差分に限定する**: 棄却。実PR3件で測定した結果、効果はPRの
  性質に強く依存する。本プロジェクトが日常的に扱う題材の名称データを追加する
  種類のPRでは、範囲を差分に限定してもヒット数がファイル全体走査と同水準の
  ままだった。
- **除外リストの導入**: 棄却。対象となる名称は増え続けるため一覧の保守が
  破綻し、追記漏れがそのまま検出漏れに直結する。

## 決定の理由

- 検出すべき実在の個人情報が実測で0件である一方、誤検出は構造的に不可避
- 常時失敗する検査を常時実行のゲートに置くと、失敗が常態化して検査が
  形骸化する
- 形骸化した検査は検査が無い状態より悪い（通過したことの意味が失われる）

## 帰結

- **手動運用の実績**: 本調査で作成したIssue・コメントの下書き12件のうち、
  実際に投稿した10件はいずれも投稿前の走査で検出0件だった。重複のため
  投稿を見送った下書き2件のうち1件は0件、1件は投稿前の時点で1件ヒットして
  おり、投稿を止める判断が機能した。手動運用でも投稿前の走査は引き続き
  必須である。
- **残る前提**: Issue #257（CLI の終了コードが3通りの状態を区別できない
  欠陥）は、手動運用であっても解消が望ましい。検出なしと実行失敗を
  終了コードだけでは判別できないままだと、通過を誤って信頼しかねない。
- **再検討時の前提**: 差分限定の実装障害3点（行番号の逆引き不能・基準参照
  不在時の無効化・差分の先頭記号による誤検出）は Issue #258 に記録済みで、
  将来 verify.sh 統合を再検討する場合の出発点として残す。
