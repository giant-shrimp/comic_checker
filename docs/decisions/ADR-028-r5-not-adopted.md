# ADR-028: ラベル規則v3のR5をjudge()の実装要件として採用しない

- 日付：2026-09-24
- 状態：採用

## 背景

Issue #159は、ラベル規則v3のR5（第1部完結後の散発的掲載で、直近12か月以内の
掲載があれば連載中、無ければ判定不能とする規則）に対応するコード実装が無いこと
を報告し、実測されている影響としてD_error 1件を挙げている。

R5の根拠を確認したところ、以下が判明した。

- R5は作業94-1（2026-08-13、ラベル規則v1）で導入されて以来、v2（R3修正版）・
  v3（作業98-A-1）を通じて条件文が変更されていない。v3の監査
  （`docs/holdout_measurement_2026-08/step98_a_labeling_rules_v3.json`の
  `audit`配列、`rule_id: "R5"`のエントリ）は「`revised_rule: null`」
  「R5は変更しない」としており、かつ100件の再適用でR5が適用された行は
  0件だった（`empirical_check.method`：「100件中、rule_applied=R5の行は
  0件。」）。
- R5の根拠となった実データ上の事例は、v1〜v3を通じて1件のみである
  （`docs/holdout_measurement_2026-08/step98_a3_labels.json`・
  `docs/holdout_measurement_2026-08/step98_b_compare_result.json`の
  いずれでもR5適用行は1件のみ）。この1件と独立した実データでの検証は
  行われていない。
- `README.md`「### Wikipedia判定（既定の経路）」節が述べる本ツールの定義は、
  「記事のリード文（冒頭）を文単位で見て、『〜連載中』（現在形）と『〜まで
  連載された』『〜をもって完結した』（過去形）を区別して判定する」という
  ものであり、散発的な新作掲載の有無によって連載中側へ倒す規定を含まない。
- Issue #159が挙げるD_error 1件の実例は、本文に明示的な連載終了宣言があり、
  `COMPLETED_WEAK_RE`がこれを正しく拾って完結と判定したものである。これは
  上記のREADMEの定義どおりの挙動であり、定義から逸脱した誤判定ではない。

## 決定

1. **R5を`judge()`の実装要件として採用しない。**
2. **Issue #159を`judge()`の欠陥として扱わない。** Issue #159が報告する
   D_error 1件は、未検証のラベル規則（R5）と、文書化された本ツールの定義
   （README記載の完結/連載判定基準）との食い違いであり、コード側の欠陥とは
   断定できない。

## 検討した案と棄却理由

- **R5を採用し、未消費プール（現在142件、後述）から抽出して構造検出を
  実装する案**: 棄却。R5の根拠が独立データで検証されていない1件のみである
  ため、実装に着手しても、その実装が正しく一般化するかを判断する材料が
  無い。Issue #159本文自身も「規則の一般化可能性も未確認」「実装の複雑さが
  他系統より高く、判別力の測定自体が実データ取得後でなければ評価できない」
  と述べており、着手の前提条件が現時点で揃っていない。
- **現状維持（Issue #159をOPENのまま、判断を保留する）**: 棄却。R5の検証
  可能性・本ツールの定義との整合性は、本ADRの検討で確認できる材料が既に
  揃っており、判断を先送りする理由がない。判断を確定させ、再検討の条件を
  明記するほうが、次に着手を検討する人にとって有用である。

## 決定の理由

- fail-closed原則（Issue #8以来: 裏付けの取れない断定を避け、確信が持てない
  場合は判定不能に倒す）に照らすと、根拠1件のみの規則を実装要件として採用
  することは、逆に根拠の薄い断定を実装へ持ち込むことになりかねない。
- 本ツールの完結/連載判定の定義（README記載）と、R5が要求する挙動（散発的な
  新作掲載があれば連載終了宣言後でも連載中とする）は、そもそも前提が異なる。
  定義を変更するに足る独立した実データでの裏付けが無い時点で、定義と異なる
  挙動を欠陥として扱うのは早計である。

## 帰結

- **過去の測定結果ファイル（`step98`の比較結果等）のD_error集計は書き換え
  ない。本ADRがその解釈を限定する。** D_error 1件という集計値自体は実測の
  記録として維持し、その1件を「コードの欠陥」ではなく「未検証のラベル規則
  との食い違い」として扱う、という解釈のみを本ADRが与える。
- **再検討の条件**: R5のパターンの実例を、既存の1件とは独立した実データで
  複数得て、事前登録を行ったうえで再検討する。
- Issue #159本文が完了条件として挙げる「未消費262件」は、
  `docs/code_defects_2026-08/holdout_pool_consumption_ledger.json`の
  `note_on_262_references`が記録するとおり2026-08-13〜2026-08-21の間だけ
  正しかった中間値であり、現在の未消費件数は142件（`current_remaining`）
  である。
