# ADR-025: 棚卸し表の見出し列をERRORS.mdの見出しと完全一致させ、同定キーとする

- 日付：2026-09-19
- 状態：採用

## 文脈

`docs/errors_md_inventory.md`（ERRORS.mdの棚卸し表）は、各記録の位置を
「開始行-終了行」という行範囲でのみ同定してきた（`scripts/check_errors_inventory.sh`
検査3・検査5、Issue #286・#292）。行範囲だけを同定手段とした場合、ERRORS.mdの
どこか1箇所に行が挿入・削除されると、それより後にある記録はすべて行範囲が
実測とずれる。

Issue #281の検討のため、この挙動を実測した（対象実装は現行の検査3・検査5、
改変はいずれもメモリ上のみでファイルへは書き戻していない）。最初の記録の
本文へ1行を挿入した場合、検査3が60件・検査5が60件鳴った一方、実際に内容が
変わった記録は0件だった（挿入箇所は分類表に対応行を持たない見出しの本文で
あり、行範囲を持つ60記録はいずれも内容不変で位置のみ1行ずれた）。中ほどの
1記録の本文へ5行を挿入した場合も、検査3が31件・検査5が30件鳴ったが、実際に
内容が変わった記録は1件のみだった。行範囲による同定は、どの記録が実際に
変わったかを示さず、変更点より後にある無関係な記録すべてを道連れにする。

既存の見出し列はERRORS.mdの見出し行の写しではない。行範囲を持つ60行を
ERRORS.mdの実際の見出し（`## `を除いた文字列）と突き合わせた実測では、
完全一致は23件のみで、前方一致（棚卸し表側が短い真部分文字列）が2件、
残り35件はどちらの関係も持たなかった。この状態では、見出し文字列を
そのまま同定キーとして使っても機能しない。行挿入・記録削除のいずれの
改変を加えても、一致・不一致の判定結果（一意に決まる件数25件・決まらない
件数44件）は改変前後で一切変化しなかった（差分0）。変わったはずの記録
（本文へ5行挿入した記録、または削除した記録）も、改変前から既に「欠落」
（一致するERRORS.md見出しが無い）に分類されていたため、変化そのものが
観測できなかった。

## 決定

1. **棚卸し表の見出し列を、ERRORS.mdの見出し行（`## `を除いた文字列）と
   完全一致させ、同定キーとして用いる。** 前方一致・部分一致は同定キーとして
   採用しない（完全一致でなければ、どの記録に対応するかが一意に定まらない）。
2. **見出し列とERRORS.md実体との完全一致を、検査6として機械的に強制する。**
   行範囲を持たない9行（退避先の記載等）は突き合わせ先が無いため、検査6の
   対象外とする。
3. **ハッシュ列・ID列は導入しない。** 既存の見出し列を実体に合わせて同期する
   方が、69行すべてへの新規列追加と、以後その列を更新し続ける運用コストより
   安いため。

## 決定の根拠と、採らなかった案

- **ハッシュ列を追加する案**: 却下。ハッシュ値は本文（またはその一部）から
  機械的に導出される値であり、記録の本文が正当に更新されるたびに再計算・
  再記載が必要になる点で、見出し列を実体に合わせて更新する運用と労力の
  性質が変わらない。列を1つ増やす分だけ実装・検査対象が増えるが、決定2の
  機械的検査で得られる保証（実体との完全一致）は見出し列の同期だけで
  既に得られており、ハッシュ列を追加する追加の利益がない。
- **ID列を追加し、ERRORS.md側にも対応するIDを埋め込む案**: 却下。ERRORS.md
  自体への書き込みが必要になるが、本Issueの範囲はERRORS.mdを変更しないこと
  を前提としている。ERRORS.mdは失敗記録そのものを書く場所であり、棚卸し表側の
  都合（同定手段）のために本体へ機械可読な注記を追加することは、ERRORS.mdの
  性質（読解のための記録）と棚卸し表の性質（分析用の副次文書）の境界を越える。
- **現状維持（行範囲のみで同定し、見出し列は放置する）案**: 却下。現状の
  ままでは、見出し列の44/69が実体と対応しないままになり、かつ行範囲のみの
  同定が引き起こす「無関係な記録すべてが道連れで検査に引っかかる」という
  挙動（文脈節の実測）も解消しない。据え置くことで得られる利益がない。

## 代償

見出し列の文字数は、ERRORS.mdの実際の見出し文字列の長さに揃うため、最長で
84文字まで伸びる（実測。手順2参照）。表が横に長くなるが、各記録の説明・
根拠は根拠列が担っており、見出し列自体に説明を追加する必要はないため許容する。

## 残る限界

見出し文字列そのものが書き換えられた場合は、この手段でも同定できない。
検査6は「棚卸し表の見出し列とERRORS.mdの実体が食い違っている」ことは
検出できるが、書き換え後のどの見出しが元のどの記録に対応するかを追跡する
手段ではない。見出しの言い換え（リネーム）が発生した場合、検査6は不一致
として鳴るが、対応関係の復元は引き続き人手に依存する。
