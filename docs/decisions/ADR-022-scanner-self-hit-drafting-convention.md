# ADR-022: 走査器の自己ヒットに対し、下書き作成時の明文の運用規約を定める

- 日付：2026-09-16
- 状態：採用

## 背景

Issue #271に事例が4件蓄積されている。内訳は、実在の作品名が敬称と同型の語尾の
形を持つために検出される類型が2件、外部に出す文書を書く行為そのものが検出を
招く自己ヒットの類型が2件である。

自己ヒットの2件は、それぞれ異なるパターンで発生した。一方は敬称の形を見る
パターン、もう一方はユーザディレクトリを指す接頭辞の形を見るパターンである。
異なる2つのパターンで同じ構造（文字列の形式のみを基準とした一致判定であり、
出現文脈を区別しない）が観測されている。

ADR-017（`docs/decisions/ADR-017-scanner-verify-integration-not-adopted.md`）は
既に、検出パターンの絞り込み案を「誤検出を大幅に減らせる境界条件は存在するが、
同じ条件が実在人名の典型形（2文字以上の名前の2文字目に敬称が続く形）も
同時に除去してしまう。誤検出と検出漏れがパターン側では分離できない」として
棄却している（「検討した案と棄却理由」節）。本ADRはこの決定を覆さない。

## 測定

実測日: 2026-09-16。以下はすべて本ADR作成のために実行したコマンドの出力である。

**1. 走査器のパターン定義の行番号**
（`grep -n 'HOME_PREFIX_PATTERN = re.compile\|EMAIL_PATTERN = re.compile\|HONORIFIC_PATTERN = re.compile\|HONORIFIC_EXCLUDE_PATTERN = re.compile' scripts/check_no_personal_info.py`）:

```
55:HOME_PREFIX_PATTERN = re.compile(
60:EMAIL_PATTERN = re.compile(
68:HONORIFIC_PATTERN = re.compile(
78:HONORIFIC_EXCLUDE_PATTERN = re.compile(
```

**2. docstringが定める除外語彙の追記運用**
（`nl -ba scripts/check_no_personal_info.py | sed -n '14,24p'`、要旨のみ引用。
除外語彙一覧に実際に載っている個別の語は本ADRには書かない）:

15-21行目に、除外語彙の一覧は有限の列挙であり網羅性を保証しないこと、新しい
誤検出が見つかるたびに一覧へ語を追記する運用とすることが明記されている。

**3. Issue #271のコメント件数**
（`gh issue view 271 --json comments -q '.comments | length'`）:

`4`。

## 決定

1. **走査器のパターン定義・除外語彙を、本ADRでは変更しない。**
2. **外部に出す文書の下書きでは、走査器のパターンと同じ形を持つ表現を
   用いないことを明文の運用規約とする。** 対象は次の4種とする。
   - 実在の作品名
   - 敬称と同型の説明語彙（1文字＋敬称の形になる語）
   - 絶対パスの形（CI実行環境の作業ディレクトリを示すものを含む）
   - 走査器のパターン定義そのもの（正規表現ソース）
3. **除外語彙の追記は、実在の作品名の類型に対してのみ行う。** 自己ヒットの
   類型は除外語彙の追記では解消しないため、追記の対象としない。

## 決定の理由

- 除外語彙の追記は、実在の作品名が特定のパターンに一致する類型にしか効かない。
  自己ヒットの類型のうち、ユーザディレクトリを指す接頭辞の形に当たった事例は、
  パターン定義そのものを弱めなければ除外できず、それは実在の個人のディレクトリ
  パスの検出漏れに直結する。ADR-017が既に指摘した「誤検出と検出漏れがパターン
  側では分離できない」という構造が、この類型にもそのまま当てはまる。
- 決定2の運用規約は、既に事実上運用されている。Issue #271の事例整理コメント
  自体がこの規約に沿って（実例を挙げず形の説明にとどめて）書かれ、投稿前の
  走査を検出0件で通過している。
- 明文化されていない運用ルールは、権限設定ファイルの確認だけでは発見されない
  という教訓が`ERRORS.md`に既に記録されている。本ADRはこの教訓を踏まえ、
  既に事実上運用されている規約を明文化する。

## 限界

- 本ADRは誤検出そのものを減らさない。実在の作品名を含む成果物
  （ラベルデータ・測定結果等）を走査した場合の検出は、決定3のとおり除外語彙が
  追記されない限り残る。
- 決定2の運用規約は人間・AIいずれの側でも遵守に依存しており、機械的な強制
  手段は無い。
- 事例は4件に限られる。他のパターン（メールアドレスの形を見るもの等）で
  同種の構造が生じるかは未観測である。

## 見直す条件

決定2の運用規約に従って書いた下書きが投稿前走査に止められる事例が新たに
発生した場合、または走査器に出現文脈を区別する機構が導入された場合。その
時点で得られる観測データを根拠に、本ADRの決定を再検証する。
