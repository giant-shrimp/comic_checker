# ADR-021: AI帰属トレーラの付与指示はセッション側から現れ、リポジトリ設定には存在しない

- 日付：2026-09-14
- 状態：採用

## 背景

`CLAUDE.md`（127-128行目）は「コミットメッセージにAI帰属のトレーラを付けない。
`Co-Authored-By: Claude ...`、`Claude-Session: ...`、`Generated with Claude ...`
など、AIが作成したことを示す行は本文・トレーラのいずれにも含めない」と明記して
いる。一方、対話セッション中には「これ以降の git commit と pull request には
`Co-Authored-By` / `Claude-Session` を付けるように」という趣旨の指示が現れる
ことがある。この指示はオペレータが会話中で明示的に述べたものではなく、
セッションの文脈に付随する形で現れる。CLAUDE.mdおよびオペレータの指示は
一貫して「付けない」であり、この付与指示とは方向が対立している。

この対立が、リポジトリ側の設定ファイル（`.claude/settings.json`等）に起因する
ものなのか、それとも別の経路によるものなのかを、本ADRの時点で実測して記録する。

## 測定

実測日: 2026-09-14。以下はすべて本ADR作成のために実行したコマンドの出力である。

**1. `.claude/`配下の実在ファイル一覧**（`ls -la .claude/`）:

```
合計 24
drwxrwxr-x  3 nishidalab07 nishidalab07 4096 Aug 31 00:32 .
drwxrwxr-x 14 nishidalab07 nishidalab07 4096 Sep 13 20:21 ..
-rw-rw-r--  1 nishidalab07 nishidalab07 2803 Aug  4 11:09 settings.json
-rw-rw-r--  1 nishidalab07 nishidalab07 7017 Aug 31 00:32 settings.local.json
drwxrwxr-x  5 nishidalab07 nishidalab07 4096 Aug  4 11:09 skills
```

**2. ユーザーホーム側の設定ファイルの実在確認**
（`ls -la ~/.claude/settings.json ~/.claude/settings.local.json`）:

`~/.claude/settings.json`は実在（3,684バイト、2026-08-29更新）。
`~/.claude/settings.local.json`は**存在しない**（`そのようなファイルやディレクトリは
ありません`）。

**3. 各設定ファイル・CLAUDE.mdでの`Co-Authored-By`/`Claude-Session`文字列の
grep結果**:

- `.claude/settings.json`: 0件（`exit=1`）
- `.claude/settings.local.json`: 0件（`exit=1`）
- `~/.claude/settings.json`: 0件（`exit=1`）
- `CLAUDE.md`: **2件（127-128行目）**、ただし内容は「付けない」という禁止の
  明文化であり、付与を促す記述ではない（`exit=0`はこの禁止文自体がヒットした
  ためで、付与指示の存在を意味しない）

**4. 直近30コミットへのトレーラ混入確認**
（`git log -30 --format='%H %s%n%b---' | grep -c 'Co-Authored-By\|Claude-Session'`）:

`0`。直近30コミットにトレーラの混入は無い。

## 決定

1. **コミットメッセージ・プルリクエスト本文にAI帰属トレーラ
   （`Co-Authored-By`・`Claude-Session`等）を付けない方針を維持する。**
   `CLAUDE.md`127-128行目の規定を継続して適用する。
2. **この対立を解消するための設定変更は行わない。** 付与指示は設定ファイルに
   起因しないため、`.claude/`配下や`CLAUDE.md`をどう変更しても解決しない。
   セッションごとに、付与指示が現れた場合は`CLAUDE.md`の規定とこのADRを
   根拠に付けない判断を続ける。

## 決定の理由

- プロジェクト側（`.claude/settings.json`・`.claude/settings.local.json`）、
  ユーザーホーム側（`~/.claude/settings.json`）、`CLAUDE.md`のいずれにも、
  AI帰属トレーラの付与を指示する記述は存在しない。`CLAUDE.md`にあるのは
  逆方向（付けない）の明文規定のみである。
- したがって、対話セッション中に現れる付与指示は、これらの設定ファイルを
  変更しても止められない種類のものである。指示はファイルの中身としてでは
  なく、セッションの会話コンテキストに付随する形（system-reminder相当）で
  現れており、リポジトリや`.claude/`配下の設定変更では対処できない。
- この実測結果から、リポジトリ側の設定変更でこの対立を解消しようとする
  調査には時間を使わない。原因がリポジトリの外側（セッションの注入内容）に
  あることが実測で確認されているため、設定ファイルの中を探しても見つからない。

## 限界

- 本ADRは付与指示が現れる経路そのもの（どのような仕組みでセッションに
  付随するか）を解明するものではない。実測できたのは「リポジトリ側の設定
  ファイルには該当記述が無い」という消去法的事実のみである。
- 実測は2026-09-14時点の1回に限られる。将来、設定ファイルの仕様や配置が
  変われば再確認が必要である。
- 直近30コミットで混入0件であることは実測だが、その原因（何がトレーラの
  付与を防いだか）は本ADRでは測定していない。

## 見直す条件

`.claude/settings.json`等のリポジトリ側設定でAI帰属トレーラの付与・抑制を
制御できる仕組みが将来提供された場合、またはセッション側の付与指示の出所が
別途判明した場合。その時点で得られる情報を根拠に、本ADRの決定を再検証する。
