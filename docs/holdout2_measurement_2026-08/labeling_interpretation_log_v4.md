## I-001: 複数 Infobox animanga/Manga ブロックを持つ記事における R3' の評価単位

- **論点**: 1記事のwikitextに `{{Infobox animanga/Manga}}` ブロックが複数存在する場合
  （同一作品が続編・改題・移籍等で複数期に分かれて連載され，各期ごとに別ブロックが
  立てられているケース），R3'（終了号または終了日が非null，かつ値に「連載中」を含まない
  場合に完結とする規則）をどの単位で評価するか。v4規則本文はこの点を規定していない。
- **初出区間**: 区間2（31〜60件目）。
- **検討した選択肢**:
  - (a) 記事全体でwikitext中に最初に出現するブロックで評価する
  - (b) 全ブロックのいずれか1つでも該当すれば発火する
  - (c) 最新（wikitext中で最後に出現する＝時系列的に最も新しい）ブロックで評価する
- **採用した解釈**: (c) 最新ブロック優先。
- **採用理由**: 複数ブロックは同一作品の異なる時期の連載期を表しており，「現在この
  作品は連載中か」という問いに答えるには，過去に完結した旧期ではなく，時系列的に最新の
  期の状態を見るのが人間の読解として自然である。旧期の終了フィールドで機械的に完結と
  判定すると，最新期が明示的に連載中であっても見落とすことになり，R3'の趣旨
  （フィールドの値を読まずに機械的判定することを避ける）に反する。
- **適用済み該当件数とtitle（区間2時点）**: 2件。
  - 戦う!セバスチャン（旧3ブロック完結済み，最新ブロックは終了号・終了日とも空欄 →
    連載中と判定）
  - 彼女のカレラ My Favorite Carrera（旧2ブロック完結済み，最新ブロックの終了日欄に
    文字通り「連載中」と記載 → R3'除外規定に該当し連載中と判定）

- **区間1（1〜30件目）への遡及適用結果**: 複数Mangaブロックを持つ記事は3件存在した
  （ちいさいひと 青葉児童相談所物語＝2ブロック，清村くんと杉小路くんと＝3ブロック，
  月の夜 星の朝＝3ブロック）。全件について全ブロックの終了号・終了日を再確認したところ，
  **いずれの記事も全ブロックが終了済み（非null・「連載中」不含）であり，ブロック間の
  終了状況に矛盾は無い**。したがって(a)(b)(c)いずれの解釈を採っても結果は同一（完結）
  であり，現在のラベル（いずれも完結・R3'該当）はI-001の解釈と整合している。
  **修正なし。** 検証に用いたコマンドと出力は本文書末尾を参照。

- **区間2（31〜60件目）への適用確認結果**: 複数Mangaブロックを持つ記事は6件存在した
  （アイドライジング!＝2ブロック，戦う!セバスチャン＝4ブロック，超犬リープ＝2ブロック，
  彼女のカレラ My Favorite Carrera＝3ブロック，フルアヘッド!ココ＝3ブロック，
  ひぐらしのなく頃に 巡＝2ブロック）。このうち「戦う!セバスチャン」「彼女のカレラ」の
  2件はブロック間で終了状況が食い違い（旧ブロック完結・最新ブロック未完結），既に
  報告済みの通りI-001解釈(c)を適用済みで整合している。残り4件（アイドライジング!・
  超犬リープ・フルアヘッド!ココ・ひぐらしのなく頃に 巡）は全ブロックが終了済みで
  食い違いが無く，(a)(b)(c)いずれでも結果は同一（完結）である。**修正なし。**

```python
with open('docs/holdout2_measurement_2026-08/holdout2_wikitext.json', encoding='utf-8') as f:
    d = json.load(f)
rows = d['rows']
target = [r for r in rows if r['wikitext'] is not None]
seg = target[0:60]  # 区間1+2

def extract_manga_blocks(wikitext):
    results = []
    for m in re.finditer(r'\{\{Infobox animanga/Manga', wikitext):
        idx = m.start()
        depth = 0
        i = idx
        n = len(wikitext)
        while i < n-1:
            if wikitext[i:i+2] == '{{':
                depth += 1; i += 2; continue
            if wikitext[i:i+2] == '}}':
                depth -= 1; i += 2
                if depth == 0:
                    results.append(wikitext[idx:i]); break
                continue
            i += 1
    return results

def field(block, names):
    for name in names:
        m = re.search(r'\|[ \t]*' + re.escape(name) + r'[ \t]*=[ \t]*(.*)', block)
        if m:
            return m.group(1).strip()
    return ''

for i, r in enumerate(seg, start=1):
    blocks = extract_manga_blocks(r['wikitext'] or '')
    if len(blocks) >= 2:
        print(f"[{i}] {r['input_title']}  (Manga blocks: {len(blocks)})")
        for j, b in enumerate(blocks):
            end1 = field(b, ['終了号']); end2 = field(b, ['終了日']); end3 = field(b, ['終了'])
            ended = bool((end1 and '連載中' not in end1) or (end2 and '連載中' not in end2) or (end3 and '連載中' not in end3))
```

## I-002: R3'の終了号/終了日フィールドの値が「休載中」等，完結を意味しない語のみの場合の扱い

- **論点**: R3'の除外規定は「終了号または終了日の値自体に『連載中』という文字列が含まれる場合は，
  この規則を適用しない」と定めており，明示的に列挙されているのは「連載中」という語のみである。
  しかし実際の記事では，終了号/終了日フィールドの値がそれ自体「休載中」（連載中ではなく，かつ
  完結でもない）という語のみで構成されているケースが存在する（区間3・61〜90件目の
  「ことはの王子様」，`終了` フィールドの値が文字通り「休載中」のみ）。この値は「連載中」という
  文字列を含まないため，R3'除外規定の文言をそのまま機械的に適用すると完結（R3'該当）と
  判定されてしまうが，フィールドの値そのものが休載中であることを示しており，これを「終了の
  記録」として扱うのは，R3'自身の改訂理由（値の中身を読まずに機械的に完結と誤認することを
  避ける）に反する。
- **初出区間**: 区間3（61〜90件目），該当記事「ことはの王子様」。
- **検討した選択肢**:
  - (a) 除外規定の文言（「連載中」という文字列）を厳密に適用し，「休載中」はこれに該当しない
    ためR3'を発火させる（完結と判定する）
  - (b) 除外規定の趣旨（フィールドの値を読み，完結を意味しない値であればR3'を適用しない）を
    汲み，「休載中」等，完結を意味しないことが明白な値についてもR3'を発火させず，後続の
    R4等の判定に委ねる
- **採用した解釈**: (b)。値そのものが「休載中」である場合はR3'を適用せず，R4
  （infobox_fieldsの値に「休載中」または「再開不定」が含まれ，かつ完結・打ち切りの明示的
  宣言が記事中に無い場合）の対象として扱う。
- **採用理由**: R3'の規則本文中の改訂理由（rationale）は「値の中身を一切読まずに機械的に
  完結と誤認する」ことを避けるために新設された規定であり，「連載中」という具体例はその一
  インスタンスであって，除外事由を尽くしているとは読めない。フィールドの値が「休載中」で
  ある場合に完結と判定することは，まさにこの改訂理由が回避しようとした誤りそのものである。

- **区間1・2への遡及適用が必要な可能性について（区間3時点では未確認のまま持ち越し）**:
  区間1（1〜30件目）の「みそララ」は，終了号フィールドの値に「2012年12月号」と
  「Web BULL：4号-13号（以後休載）」が併記されているケースで，本論点発生前に選択肢(a)
  （厳密な文言適用）でR3'を発火させ完結と判定していた。I-002で(b)を採用した現在の解釈と
  整合するかどうかは，区間3時点では未検討のまま次回に持ち越した。**区間4着手前の再検討
  結果は下記「I-002の適用範囲：ケースα／ケースβの区別」節を参照。**

### I-002の適用範囲：ケースα／ケースβの区別（区間4着手前に追記）

I-002発見時点では「終了号/終了日フィールドの値が休載等，完結を意味しない語である場合」を
一括りに論じていたが，実際には構造の異なる2パターンが存在することが分かったため，ここで
明文的に切り分ける。

- **ケースα（単独値型）**: フィールドの値が非完結語（「休載中」「再開不定」等）のみで
  構成され，終了を示す具体的な号数・日付等の情報が一切ない。
  例: ことはの王子様（`終了` = 「休載中」）。
- **ケースβ（併記型）**: フィールドに具体的な終了時期（号数・日付）が実際に記録されており，
  それに加えて別の連載期に関する休載の注記が併記されている。
  例: みそララ（`終了号` = 「2012年12月号」＋「Web BULL：4号-13号（以後休載）」）。

**I-002の解釈(b)がどちらに及ぶか**の検討:

I-002の採用理由は「フィールドの値の中身を一切読まずに機械的に完結と誤認することを避ける」
ことにあった。この理由が成立するのは，値そのものが完結を意味する情報を一切含んでいない
場合（ケースα）である。ケースβでは，「2012年12月号」という値自体が実在する具体的な
終了時期であり，かつ本文にも「2012年12月号をもって『第一部・完』と銘打たれ」という
明示的な裏付けがある——すなわち，この部分に限れば，フィールドの値を読んでもなお
「終了の記録」として正しく成立している。ケースβで生じている緊張は，「値を読まずに機械的に
完結と誤認したこと」ではなく，「1つのフィールドに，ある区切り（第一部）の終了記録と，
それに続く別の連載期に関する情報が併記されており，どちらを『現在の状態』として採用すべきか」
という，**I-001（複数Infoboxブロックにおける最新状態の優先）と同種の論点**である。
併記された「以後休載」情報自体は，「終了号フィールドの値それ自体が完結を意味しない」という
I-002の前提とは異なり，むしろ「終了記録の後に生じた，より新しい継続情報」として読むのが
適切である。

**結論: (i) I-002はケースαのみに及ぶ。** みそララは現行ラベル（完結・R3'該当，
confused=true）のまま**修正しない**。理由は上記の通り，みそララのフィールド値は
「読んでもなお完結を意味しない」ケースαとは異なり，一部は正当な終了記録として成立して
いるため，I-002の適用対象外と判断したためである。ただし，みそララについて既に記録した
confused=trueの緊張関係（R3'の機械的発火とR5相当パターンとの緊張）自体は引き続き有効な
指摘であり，別途I-001とは異なる第三の論点（1フィールド内での区切り情報と継続情報の併記）
として将来的に整理する余地があることを付記する。

## I-003: 終了号/終了日フィールドの値が，終了時期を示さない断片（雑誌名等）のみである場合の扱い

- **論点**: 区間4・91〜119件目の「ローカル女子の遠吠え」で，`終了号` フィールドの値が
  文字通り「（まんがタイム）」という雑誌名の断片のみで構成されているケースに遭遇した。
  これは日付や号数を一切含まず，本文（extract）では「『まんがタイム』での連載は継続」と
  明記されている。I-002（ケースα）が扱う「休載中」等の**明示的な非完結キーワード**とは
  異なり，この値は**そもそも終了に関する情報を一切持たない断片**である（開始号フィールド
  に列挙された複数の連載期の末尾に対応する終了号が空欄のまま，雑誌名の注記だけが
  取り残されたと見られる編集上の名残）。
- **初出区間**: 区間4（91〜119件目），該当記事「ローカル女子の遠吠え」。
- **採用した解釈**: 終了号/終了日フィールドの値を読んでも実質的な終了時期の情報が
  一切得られない場合（雑誌名の断片・空の括弧書き等），R3'の「終了の記録」としては
  扱わない（R3'は不成立とする）。フィールドの非null判定は文字列の存在ではなく，
  値が実際に終了時期を伝えているかどうかで行う。
- **採用理由**: R3'自身の改訂理由（値の中身を読まずに機械的に完結と誤認することを
  避ける）は，値が非完結キーワードである場合（I-002）だけでなく，値が単に終了情報を
  含まない断片である場合にも同様に当てはまる。「フィールドが非null（何らかの文字列が
  入っている）かどうかだけを見て『終了の記録がある』と判断する」ことを避けるという
  R3'の趣旨に照らせば，情報量ゼロの断片を終了記録として扱うことも同種の誤りである。
- **区間1〜4（119件）への遡及確認（統合作業時に機械的走査で再実施）**: 初出時点
  （区間4）では「フィールド値のうち数字・年号を含まないものを目視で確認した」とだけ
  記録し，検証コマンドを残していなかった。これは本プロジェクトで問題視されている
  「数値・判定結果の導出コマンドを記録しない」という既知の再現性欠落そのものであり，
  統合作業（4分割ファイル統合ブロック）で以下の機械的走査により置き換えた。

  **判定基準**: 各Manga系インフォボックスブロックの `終了号`/`終了日`/`終了` フィールド
  値について，(1) HTMLタグ（`<br />`等）とHTMLコメット（`<!--...-->`）を除去し，
  (2) 空白・括弧・スラッシュ等の記号を除去した残りの文字列に，半角・全角を問わず
  数字が1文字も含まれない場合を候補とする。

  ```python

  with open('docs/holdout2_measurement_2026-08/holdout2_wikitext.json', encoding='utf-8') as f:
      d = json.load(f)
  rows = d['rows']
  target = [r for r in rows if r['wikitext'] is not None]
  assert len(target) == 119

  def extract_manga_blocks(wikitext):

              if wikitext[i:i+2] == '{{':

              if wikitext[i:i+2] == '}}':
                  depth -= 1; i += 2
                  if depth == 0:
                      results.append(wikitext[idx:i]); break
                  continue
              i += 1
      return results

  def field_all(block, names):

      for name in names:

          if m:
              vals.append(m.group(1).strip())
      return vals

  def strip_noise(v):
      v = re.sub(r'<[^>]+>', '', v)          # HTMLタグ・HTMLコメント除去
      v = re.sub(r'\{\{[^}]*\}\}', '', v)    # 残存テンプレート断片除去
      v = re.sub(r'[\s()（）\[\]【】/／\-・、,.。]', '', v)  # 空白・記号除去
      return v

  def has_digit(v):
      return bool(re.search(r'[0-9０-９]', v))

  candidates = []
  ```
