# holdout2 ラベル再付与における読解者内不一致の記録

## 1. 背景

ラベル付与作業の途中（91件目付近）でコンテキスト圧縮が発生し，1〜90件目の個別判断根拠が
失われた。このため全119件の読解をやり直した。圧縮前に残っていたのは区間別集計値のみである。

## 2. 目的

第1回と第2回の判断がどの程度一致するかを，取得可能な粒度で記録する。

## 3. 方法

区間A(1-30)・B(31-60)・C(61-90) の status 内訳を対比した。算出に用いたコマンドは以下の通り。

```python
import json
from collections import Counter

with open('docs/holdout2_measurement_2026-08/holdout2_labels_auto.json', encoding='utf-8') as f:
    data = json.load(f)

labels = data["labels"]
STATUS_ORDER = ["連載中", "完結", "判定不能"]

def region_counts(lo, hi):
    chunk = labels[lo-1:hi]
    sc = Counter(x["expected_status"] for x in chunk)
    confused_n = sum(1 for x in chunk if x["confused"])
    return [sc.get(s, 0) for s in STATUS_ORDER], confused_n

regions = [("A(1-30)", 1, 30), ("B(31-60)", 31, 60), ("C(61-90)", 61, 90)]

current_by_region = {}
current_confused_by_region = {}
for name, lo, hi in regions:
    counts, cf = region_counts(lo, hi)
    current_by_region[name] = counts
    current_confused_by_region[name] = cf

pre_by_region = {
    "A(1-30)": [4, 20, 6],
    "B(31-60)": [4, 25, 1],
    "C(61-90)": [3, 26, 1],
}
pre_confused_by_region = {"A(1-30)": 4, "B(31-60)": 4, "C(61-90)": 3}

for name, lo, hi in regions:
    diffs = [c - p for p, c in zip(pre_by_region[name], current_by_region[name])]
    abs_sum = sum(abs(d) for d in diffs)
    min_change = abs_sum // 2
    # ... 区間ごとの pre/cur/diff と min_change を出力

# 全体合計（連載中/完結/判定不能）と confused 合計を pre/cur で比較
# 全119件の status_counts (連載中/完結/判定不能) を再確認
```

`pre_by_region` および `pre_confused_by_region` の数値は，コンテキスト圧縮前に報告済みだった
区間別集計値（連載中/完結/判定不能の順で 4+4+3 / 20+25+26 / 6+1+1，confused が
区間A〜Cで 4/4/3）をそのまま用いた。`current_by_region` 以降は
`holdout2_labels_auto.json` の `labels` 配列（第2回・現在のファイル内容）から算出した。

区間ごとの最小変化件数は，3 status のうち差分絶対値の合計を 2 で割って算出した
（各区間は30件で固定のため，増えたぶんと減ったぶんは必ず対になる。対になる入れ替わり
1件につき差分絶対値は2生じるため，差分絶対値合計÷2が入れ替わり件数の下限になる）。

## 4. 結果

### 4.1 対比表（前回報告の表をそのまま転記）

区間別 status 内訳（連載中 / 完結 / 判定不能 の順）:

| 区間 | 第1回（圧縮前報告値） | 第2回（今回算出値） |
|---|---|---|
| A (1-30) | 4 / 20 / 6 | 3 / 21 / 6 |
| B (31-60) | 4 / 25 / 1 | 4 / 24 / 2 |
| C (61-90) | 3 / 26 / 1 | 2 / 26 / 2 |
| 合計 (1-90) | 11 / 71 / 8 | 9 / 71 / 10 |

confused 件数（区間別）:

| 区間 | 第1回 | 第2回 |
|---|---|---|
| A (1-30) | 4 | 8 |
| B (31-60) | 4 | 6 |
| C (61-90) | 3 | 3 |
| 合計 (1-90) | 11 | 17 |

区間別の status 差分（第2回 − 第1回）と最小変化件数:

| 区間 | 連載中 | 完結 | 判定不能 | 差分絶対値合計 | 最小変化件数（下限） |
|---|---|---|---|---|---|
| A (1-30) | -1 | +1 | 0 | 2 | 1 |
| B (31-60) | 0 | -1 | +1 | 2 | 1 |
| C (61-90) | -1 | 0 | +1 | 2 | 1 |
| 合計 | -2 | 0 | +2 | 6 | 3 |

### 4.2 合計値の関係（作業1の結果）

- a. 区間A+B+C（1〜90件目）の今回算出値の合計: 連載中 9 / 完結 71 / 判定不能 10（合計90）
- b. 圧縮前報告値の合計: 連載中 11 / 完結 71 / 判定不能 8（合計90）
- c. 全119件の合計: 連載中 13 / 完結 93 / 判定不能 13（合計119、`status_counts` と一致することを再確認）

status 別に見ると，完結の合計のみ両回で一致（71＝71）し，連載中（9 対 11）と判定不能
（10 対 8）はそれぞれ一致しない。ただし連載中の差分（-2）と判定不能の差分（+2）は符号が逆で
絶対値が等しく，合算するとゼロになる。この結果，1〜90件目の総件数（90）およびstatusを
問わない合計は両回で一致する一方，区間別・status別の内訳は一致しない。すなわち
「区間別には不一致だが全体合計は一致している」という関係は成り立つ。

## 5. 所見

- 3区間すべてで status 内訳に差異があった。
- 全体合計が一致しているのは区間間で差異が相殺した結果であり，合計の一致は再現性の根拠
  として使用できない。
- 変化した項目数の下限は3件である（区間A・B・Cで各1件以上）。区間内で相殺した入れ替わりは
  検出できないため，これは下限値であり，実際の項目単位不一致率は 3/90 = 3.3% 以上である。
- confused 件数は区間A〜Cで 11件 → 17件に増加した。
- 第1回の項目単位データは失われており，どの項目が変化したかは特定できない。

## 6. ラベルの採用方針

本測定で採用するラベルは第2回（全件を単一パスで通した判断）とする。項目単位データが
存在するのは第2回のみであるため。

## 7. 後続測定への含意

holdout2 を用いて算出する judge() の精度値には，上記のラベル誤差が下限3.3%として付随する。
精度値を報告する際は必ず本記録を併記すること。ラベル誤差の項目単位での定量は別途の測定課題
とする（本文書では扱わない）。
