# confused付与手続きの追補記録（v4）

本文書は事前登録ではない。事前登録 `prereg_rules_v4.md` §7(c) 手順1「v4再ラベル付けの
完了時点で，v4における confused 件数（119件中）を確定させ，追補文書に記録する」が予定
する追補記録のうち，**件数の確定（v4再ラベル付け完了後にしか行えない部分）に先立ち，
confusedをどのように生成するかという手続き自体を固定するもの**である。件数そのものは
本文書では確定しない（119件の再ラベル付けは本文書作成時点で未着手）。

## 1. 背景

v4再ラベル付けは規則（R1'・R3'・R4・R5・R2・R6）の適用によって行われる。しかしconfusedは
判定者の確信度を表す，status判定とは独立した別軸のフラグであり，規則の適用結果
（どのstatusになったか）だけからは機械的に導出できない。この論点の所在を，第2回ラベル
（`holdout2_labels_auto.json`）の実データで確認した。

導出コマンド:

```python
import json
from collections import Counter

with open("docs/holdout2_measurement_2026-08/holdout2_labels_auto.json", encoding="utf-8") as f:
    data = json.load(f)

labels = data["labels"]
cross = Counter((x["expected_status"], x["confused"]) for x in labels)
```

結果（第2回ラベル，119件）:

| status | confused=False | confused=True |
|---|---|---|
| 連載中 | 13 | 0 |
| 完結 | 80 | 13 |
| 判定不能 | 4 | 9 |
| **合計** | **97** | **22** |

判定不能でもconfused=falseの項目が4件，判定不能でなくてもconfused=trueの項目が13件
存在し，confusedはstatusと完全に一致する軸ではない（別軸）ことが確認できる。すなわち
「規則を適用してstatusを決めれば，confusedも自動的に決まる」という単純な対応関係は
実データ上も成立しない。

## 2. 第2回ラベルにおけるconfused生成方法の調査結果

`holdout2_labels_auto.json` の該当フィールドを引用する。

- `method`: 「wikitext と extract の読解による人手相当の判断。正規表現・パターンマッチ
  による自動判定は行っていない。」
- `purpose`: 「holdout2 標本119件への自動ラベル付与。judge() 未実行。」
- `process_note`: コンテキスト圧縮により1〜90件目の判断根拠が失われ全119件を読解し
  直した経緯を記す。confusedフラグ固有の付与基準への言及は無い。

これら3フィールドを含め，`holdout2_labels_auto.json` 内には**confusedフラグの付与基準を
明文で定義した記述は存在しない**。

一方，`prereg_spotcheck_20.md` 95〜98行目には次の記述がある（原文引用）。

> 「confused は，該当する記述が曖昧・不足・矛盾するなどの理由で判断に迷った項目に立てた
> フラグであり，これらは人手判断でも第2回ラベルと異なる結論に至る可能性が，confused=false
> の項目より相対的に高いと考えられる。」

この記述は，**第2回ラベル生成時点（2026-08-21T06:09:36Z）に定義された基準ではなく，
その後のスポットチェック事前登録（`prereg_spotcheck_20.md`）作成時に，既に生成済みの
ラベルに対して事後的に付された解釈**である。生成時の基準記録と事後の解釈記述は区別
して扱う。

## 3. v4における生成手続き（案1採用・確定）

ユーザ決定に基づき，以下の手続きを確定する。

- 判定者は，v4の119件再ラベル付け作業において，各項目のstatus判定を行う際に，
  「該当する記述が曖昧・不足・矛盾するなどの理由で判断に迷ったか」を主観的に自己申告し，
  confusedフラグとして記録する。
- **明文の付与基準は新設しない。** v3と同一の運用（判定者の確信度の自己申告）を踏襲する。
- **単独判定者体制とする。** v3と同じ体制であり，複数判定者による独立判定は行わない。

## 4. 案2（明文基準の新設）を採らなかった理由

案2は，R6を含む規則の適用状況とconfusedの付与を明示的に連動させる基準を新設する案
だった。この案を採らなかった理由は以下の通りである。

R6は「本文に明示的な継続/終了記述が無く，唯一の手がかりが古い巻数情報である」という，
従来v3では規則が沈黙し判定者が独自の裁量で対応していた領域（探索的診断の分類C相当）に
対して，明文の判定手続きを与える。もしconfusedの付与基準を「いずれの規則にも該当せず
確信が持てない場合」のように規則適用状況と連動させると，R6が適用される項目は「規則に
より機械的に判定不能となった」という理由でconfused=falseに転じやすくなる。

これは，事前登録§7(c)の30件歯止め（「v4のconfused件数が119件中30件を超えた場合は，
kによる判定基準を用いず，改訂が沈黙領域を埋められなかったものとして§8の失敗条件を
適用する」）の趣旨——**改訂がかえって曖昧な判断領域を増やした場合に，それをconfused件数
の増加として検出する**——を覆い隠すおそれがある。R6の新設によって規則上は「判定不能」と
いう明確な出力が得られるようになっても，判定者が実質的に感じる曖昧さ（本文に手がかりが
無い状態への不安）自体は解消されていない可能性があり，これを明文基準によってconfused=
falseへ機械的に転換してしまうと，歯止めの感度が失われる。案1（主観的自己申告を維持）は
この問題を避けられるため採用する。

## 5. §7(c) 変更禁止3点との整合確認

事前登録§7(c)が固定した3点との整合を確認する。

- **kの算出方法（v4ラベルのconfusedフラグを参照する）**: 本手続きでも，v4の119件全件に
  confusedフィールドが付与され続けるため，このフィールドを参照してkを算出するという
  方法自体に変更は無い。整合する。
- **kの確定タイミング（20件抽出直後・人手判断開始前）**: 本文書はconfusedの生成手続きを
  定めるのみであり，kの確定タイミングには関与しない。抵触しない。
- **判定式（不一致件数 > k で問題あり）**: 本手続きは判定式そのものを変更しない。抵触しない。

## 6. 分類C相当2件の評価方針（論点3）

探索的診断（`spotcheck20_diagnosis.md`）で分類Cとされた2件（No.3, No.20相当の項目）に
ついて，v4再ラベル付け完了後，以下の2点をあわせて追補文書に記録する。

- confusedの変化（第2回: true → v4: true/false）
- `applied_rule`の変化（第2回: 「なし」 → v4: 「R6」等，適用された規則の変化）

**この記録は，事前登録§6が定める通り，改訂の成否判定には用いない参考記録である。**
成否の判定は事前登録§6の新標本20件のみによって行う。confused件数の増減だけでなく
`applied_rule`の変化も併記するのは，§4で述べた「明文基準の新設により曖昧さの実態が
隠れる」リスクを踏まえ，confused件数という単一の数値だけでは捉えられない変化（規則が
明示的に適用されるようになったこと自体）を記録として残すためである。

## 7. 本手続きの限界

- confusedは判定者の主観的自己申告に依存するため，判定者の体調・集中度・その日の判断
  基準の揺れ等による変動リスクが残る。`relabel_consistency_finding.md`が記録した通り，
  同一の読解者内でも読解の反復によって判断が変化しうることは既に実証されている。
- v3とv4で判定者・判定時点が異なる（v3は`step98_a_labeling_rules_v3.json`作成時点，
  v4は本文書作成後に行われる再ラベル付け時点）。§7(c)の30件歯止めがv3の22/119を比較
  対象とすることは事前登録で固定済みだが，比較対象となる2つの数値が同一の判定基準・
  同一の判定者によって生成されたことを保証するものではない点には留意が必要である。
