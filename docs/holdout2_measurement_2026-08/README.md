# holdout2 標本

## 位置づけ

未観測の評価用標本である．

既存の holdout 99件は，系統1・案B・系統3・系統4-A・系統4-B の各検証が
毎回160件全件を走査する設計であったため実質的に全件が観測済みであり，
評価用標本として機能していない
（`docs/holdout_pool_2026-08/README.md` 管理ルール3）．

本標本は現行 `judge()` の実力を未観測の状態で測定するために取得された．

## 構成

| ファイル | 内容 |
|---|---|
| `holdout2_sample_titles.json` | 抽出された120件のタイトルと抽出条件 |
| `holdout2_wikitext.json` | 取得できた119件の extract / wikitext / revision_id |
| `extract_holdout2_sample.py` | 抽出スクリプト |
| `fetch_holdout2_wikitext.py` | 取得スクリプト |

## 抽出条件

事前登録 `docs/code_defects_2026-08/prereg_corpus_expansion_holdout2.md`
（md5 `384c77c0149c0366dcbf57012f35803e`）に基づく．

| 項目 | 値 |
|---|---|
| 抽出元 | `docs/holdout_pool_2026-08/step93_2_holdout_pool.json` の未消費262件 |
| seed | 158 |
| 抽出件数 | 120 |
| 抽出方法 | 未消費262件を昇順ソートし `random.Random(158).sample(pool, 120)` |
| 取得成功 | 119 |
| 記事なし欠損 | 1 |

記事なしとなったタイトルもプールへ復帰させない（管理ルール2）．
本標本の取得によりプール残数は142件となった．

## 既存コーパスとの関係

**統合しない．** 既存160件（regression 61 + holdout 99）とは別標本として並存させる．

既存160件は観測済みであるのに対し本標本は未観測であり，
両者を混ぜると「発見材料と評価標本の分離」が再び崩れるためである．

## 取り扱い上の注意

### 観測すると評価用標本ではなくなる

`judge()` の出力を観測した時点で，本標本は発見材料に転化する．
系統4までの反復検証が holdout 99件に対して行ったのと同じことが起きる．

したがって本標本に対する `judge()` の実行は，
事前登録が定める測定の局面に限定し，日常的な検証ループには組み込まない．

### 手順の順序

事前登録6-3が以下の順序を定めている．

1. wikitext を取得する
2. 期待ラベルを付与する（`judge()` は実行しない）
3. ラベルをコミットして固定する
4. スポットチェックを実施する
5. その後に `judge()` を実行し，照合する

ステップ3のコミット前にステップ5を実行した場合はプロトコル違反となる．

### スナップショット内の書誌情報

`holdout2_wikitext.json` には Wikipedia 由来の書誌情報（インフォボックスの
`|作者=` フィールド等）が含まれる．これは既存の `holdout_wikitext.json`・
`regression_corpus_wikitext.json` と同様であり，判定ロジックが実際に読む
入力データそのものであるためマスキングしない．

一方，PR本文・Issue本文・コミットメッセージ・報告文といった
GitHub 上で人が読む文章に，個別の作者名を列挙してはならない．
