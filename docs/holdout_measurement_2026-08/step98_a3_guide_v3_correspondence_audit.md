## 個別確認: ユーザ指摘の1〜5

### 1. ガイドの忠実性（総括）

上記対応表のとおり、R1'〜R5各条の条件・結果・例外・優先順位2組は**v3/v2の原文と
直接対応**しており、この部分の逐語性は確認できた。一方、**「基本読解」という
ガイドの土台部分は、v3のどの条文にも対応が無い。** v2/v3はいずれも「既存の
ラベルをR1'〜R5で補正する」という設計であり（v2 general_default「既存のラベルを
そのまま維持する」がその証拠）、**ゼロから連載中/完結/判定不能を導く手続き
そのものは、regulation v3の文書としてはどこにも書かれていない。** 今回のホールド
アウト100件は新規データであり「補正すべき既存ラベル」が無いため、この手続きが
不可欠になるが、v3はそれを想定していない。

### 2. 基本読解の矛盾条項とR3'例外1の衝突

**確認結果**: 衝突は実在する。ただし原因は「v3の穴」ではなく、**ガイドが独自に
書いた「矛盾→判定不能」という基本読解の一文が、v3が実際に定めている設計方針
（本文の直接記述を優先する）と整合していなかった**ことにある。

v2のR3改訂根拠（95-2）には次のように明記されている:
> 「R1・R4が既に採用している『本文の直接記述を優先する』という設計思想の延長として、
> R3に優先条件を追加する」

これはR3'の例外1が単なる場当たり的な例外ではなく、**v2/v3全体を貫く設計方針
（本文の直接記述を、インフォボックスの非nullな値より優先する）の一部**である
ことを示している。したがって、本文に明示的な継続記述があり、インフォボックスが
（年不明の）終了系フィールドを持つ場合の「正解」は、v3の設計方針に照らせば
**判定不能ではなく、本文の記述（連載中）を採用する**方向である。ガイドの
「基本読解」節がこれと矛盾する「矛盾→判定不能」という一般則を独自に書いたことが
原因であり、ガイド側の記述ミス（v3を誤って再述した）と判定する。

**ただし別の状況で本物の「v3の穴」が見つかった**: インフォボックスの終了系
フィールドが**4桁の年を含む**場合（R3'の対象外。R3'は「年を含まない」場合のみを
対象とする）に、本文の曖昧な継続示唆（現在形の明示的な継続記述とまでは言えない
表現、例:「続いている」）と矛盾するケースは、**R1'〜R5のどれにも該当せず、v3に
解決規定が無い。** 第1回検証対象のキャラ者（本文「続いている」「最新話が公開
されている」、インフォボックス終了=2008年、年入り）が実例である。これは
上記のR3'例外1（年不明の場合）とは別の、未カバーのパターンである。

### 3. R2の基準年月の所在

**確認結果**: v2/v3のR2条件文は「**extract中に**」と明記されており、本文
（リード＋最初のセクション）内の記述に限定されている。実際のデータで確認したところ:

- 春巡る（row23）: `extract`に「2014年7月」の文字列を**含む**
  （実測: `"extract contains '2014年7月': True"`）。R2の文言どおり本文中の記述であり、
  適用は妥当。
- 天使の裁量（row44）: `extract`に「既刊1巻」「2012年6月」のいずれも
  **含まない**（実測: いずれも`False`）。この基準時点はインフォボックスの
  `infobox_volumes`フィールド（`"既刊1巻（2012年6月現在）"`）にのみ存在する。

**つまり天使の裁量への元のR2的な判定不能ラベル付けは、R2条文の「extract中に」という
限定を超えて、インフォボックスの巻数フィールドの日付を根拠にしていた。** これは
R2の文言を厳密に読めば範囲外の適用である。ガイドの架空例（巻数フィールドの日付を
使った例）も、この同じ逸脱をそのまま再現していた。

**v3の穴として報告**: v2/v3のR2は本文中の古い基準時点のみを対象とし、
**インフォボックスの巻数フィールドに基づく古い基準時点の扱いを定めていない。**
コード側には類似の関心を扱う別の仕組み（Issue #56の`CONTINUATION_STALE_YEARS`、
`_has_continuation_evidence`）が存在するが、これは巻数フィールドが**空欄の終了系
フィールドを連載中と判定してよいか**という別の問題（M6-B-4）に対する仕組みであり、
R2が扱う「現在形の継続表現の基準時点の古さ」とは対象が異なる。ラベル規則v3には、
巻数フィールドの日付が古い場合に完結側の判定不能を導く規定が無い。

### 4. 優先順位の欠落組み合わせ

**確認結果**: v2の`priority_when_multiple_rules_apply`を実測確認したところ、
定義されているのは次の3組のみだった。

```
R2_vs_R5, R4_vs_R1, R3_vs_R1
```

**R3'とR4、R3'とR5、R3'とR2の組み合わせはいずれも定義されていない。** v3の穴として
報告する。ガイド側で独自の優先順位を補うことはしていない。

### 5. 「具体的な終了時期を伴わない過去形のみ」の扱い

作業4（`step98_a3_valid_findings.md`所見1）で既に「規則の穴候補」として切り出し済み。
ガイドでも対応する条文が無いことを確認した（R1'〜R5のいずれも「過去形か現在形か」
「具体的な終了時期の有無」を明示的な条件にしていない）。ガイド側での補完はしていない。
改訂案は`step98_a3_valid_findings.md`に起票用の本文案として既に提示済み（未起票）。

## 「v3の穴」一覧（7件、3件の閾値を超過）

1. **基本読解手続き自体がv3に文書化されていない。** v3/v2は既存ラベルへの補正のみを
   定義しており、新規データをゼロから判断する手続きを定めていない。
2. **R2に「基準年月が明記されない現在形記述」の扱いが定められていない。**
   本文に日付が無い現在形の継続記述をどう扱うかが空白。
3. **「いずれの規則にも該当しない場合」の新規データ向けデフォルトが無い。**
   v2の`general_default`は「既存ラベルを維持する」であり、既存ラベルが存在しない
   新規データには適用できない。
4. **インフォボックス終了系フィールドが4桁の年を含む場合の、本文の曖昧な継続示唆との
   矛盾パターンが未カバー。** R3'は年を含まない場合のみを対象とする（キャラ者が実例）。
5. **R2の適用範囲が本文中の記述に限定されており、インフォボックス（巻数フィールド等）
   に基づく古い基準時点の扱いが定められていない。** 天使の裁量の元のラベル付けは
   この隙間を埋め合わせる形でR2条文の範囲を超えて適用していた。
6. **R3'とR2・R4・R5との優先順位が未定義。** 定義されているのはR2 vs R5、R4 vs R1'、
   R3' vs R1'（無衝突）の3組のみ。
7. **「具体的な終了時期を伴わない過去形のみ」の完結根拠としての扱いが定められていない。**
   （作業4所見1で既出、改訂案は起票せず提示のみ済み）

## 停止条件2の適用

7件は3件の閾値を大きく超えている。ユーザの指示「穴が多い場合、ガイドの修正では
なくv3の改訂が先になるため」に従い、**ガイド（`step98_a3_rules_guide_for_verifier.md`）
の修正には進まない。** v3・v2の原文（`docs/`配下の凍結ファイル、
`step95_2_labeling_rules_v2.json`）はいずれも書き換えていない。上記7件は、
v3の改訂候補としてユーザの判断を仰ぐための一覧として提示するに留める。
