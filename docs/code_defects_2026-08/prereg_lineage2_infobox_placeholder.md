## 1. 対象と根拠

### 対象

`comic_checker/wikipedia_client.py`の`_judge_via_infobox()`（863行目〜）。
本編漫画のインフォボックスブロックにおいて、終了系フィールド
（`END_FIELD_NAMES` = `("終了号", "終了日", "終了")`、604行目）の値が、
`ONGOING_FIELD_MARKER`（「連載中」、860行目）も`HIATUS_MARKER`（「休載」、
849行目）も含まない非空文字列だった場合、現行コードはその値を無条件に
実際の終了値として採用し、`完結`を返す（892行目
`return "完結", f"インフォボックス: {field_name} = {value}"`）。

「？」「?」のようなプレースホルダ値（未確定・不明を表す注記であり、実際の
終了時期の記録ではない）もこの非空文字列の条件に該当するため、**根拠の無い
完結の断定に直結する**。これは判定を安全側（判定不能）へ倒す誤りではなく、
確信のない完結を確信ありとして提示する誤りであり、方向としては危険側である。

### 出典（Issue #156、実測1件）

`docs/holdout_measurement_2026-08/step98_b_compare_result.md`のNo.44
（bucket=F_unverifiable）。ラベル＝判定不能、judge()出力＝完結、evidence種類＝
インフォボックスの終了系フィールド（値はプレースホルダ）。

**この1件がD_errorではなくF_unverifiableに分類された理由を明確にしておく
（安全性の主張と取り違えないため）。** `docs/holdout_measurement_2026-08/
step98_b_compare.py`の`classify_bucket()`は、ラベルが「判定不能」の行については
judge()の出力が何であってもF_unverifiableに機械的に分類し、D_errorの対象に
ならない設計である。**F_unverifiableになったのは、人手のラベル付け自体が
確信を持てず判定不能とした行だったためであり、`_judge_via_infobox()`の
この挙動が安全だと確認されたからではない。** ラベル根拠（同ファイル）は、
本文が完結を明言していないこと、巻数フィールドも古い基準時点しか示して
いないことを挙げており、コードの挙動を免責する記述ではない。

### 危険側の判定である根拠（コード読解、実測）

`judge()`（1237行目〜）は、`_judge_via_infobox()`が返した`完結`について、
2つの上書き条件（`_has_ongoing_signal(extract)`が真の場合、または
`_is_novel_primary(extract)`かつ本文にMANGA_MARKERSが無い場合）でのみ
`判定不能`に戻す。プレースホルダに由来する`完結`は、この2条件のいずれにも
該当しない限り、そのまま`judge()`の最終出力として確定する。実測1件は
実際にこの経路を通って`完結`が最終出力になっている。

## 3. 変更案

```python
def _judge_via_infobox(wikitext, today=None):
    ...
    hiatus_field = None
    for field_name in END_FIELD_NAMES:
        value = _infobox_field(main_block, field_name)
        if not value:
            continue
        if ONGOING_FIELD_MARKER in value:
            return "連載中", f"インフォボックス: {field_name} = {value}"
        if _is_placeholder_value(value):          # 新設
            return None, None                      # 新設
        if HIATUS_MARKER in value:
            hiatus_field = hiatus_field or (field_name, value)
            continue
        return "完結", f"インフォボックス: {field_name} = {value}"
    ...
```

- **判定条件**: 終了系フィールドの値が、前後の空白を除いて「？」または「?」
  の1文字以上の並びだけからなる場合（全角・半角いずれも対象。両者の混在は
  今回の実測範囲では確認されていないため未検証のまま扱う）。
- **挙動**: 該当した場合は`完結`を返さず、直ちに`(None, None)`を返す。
  空欄の分岐（894行目〜、`_has_continuation_evidence`による連載中判定）には
  **合流させない**。プレースホルダは「継続の証拠が無ければ連載中と推定してよい
  空欄」と同列に扱う根拠が無いため（空欄は「記述が無い」ことを意味するが、
  プレースホルダは「不明であると明示された」ことを意味し、性質が異なる）。
- **後続フィールドの扱い**: 該当した場合、`END_FIELD_NAMES`の後続フィールド
  （例: `終了号`が「？」で`終了日`に実際の値がある場合）も見ない。ループを
  継続せず即座に`(None, None)`を返す。**実測（2026-09-24、`_infobox_field`を
  直接適用）**: 該当1件（「？」のみの行）では、プレースホルダが入っていた
  フィールドより後ろの`END_FIELD_NAMES`のフィールドはいずれも値を持たない
  （非空の値は無い）。したがって、この1件についてはこの後続フィールドの
  扱いが実際の判定に影響しない。後続フィールドに実際の終了値がある一般の
  ケースについては、今回の実測範囲（該当1件）では確認できないため、
  未検証のまま安全側に倒す設計とする。
- **単調性**: この変更は`完結`の出力を`判定不能`に変える方向にのみ作用し、
  `完結`を`連載中`に変える、または`連載中`/`判定不能`だった行を`完結`に
  変えることはない（`_judge_via_infobox()`内の他の分岐・条件は一切変更しない）。

（`_judge_via_infobox`単体呼び出しは用いない）。

- 変化する行が1件でない（0件、または2件以上）。
- 変化する行の変化前後の値が「完結→判定不能」以外である（例: 完結→連載中、
  連載中→判定不能等）。
- 既存テストのいずれかが失敗する。

**この予測の根拠**: 2節の実測により、対象条件（「？」「?」のみ）に該当する

判定条件に該当しないため、経路が変わらない（3節参照）。したがって、この
変更が到達しうる行は理論上1件のみである。
