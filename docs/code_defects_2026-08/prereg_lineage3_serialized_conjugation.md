    「連載された」と字面が一致せず取りこぼされる。

- Issue #157本文が挙げる「最低必要事例数10件」は、`prereg_withdrawal_record.md`で

## 2. 変更案の明示

（本体2節から変更なし）

### 現行コードの実測引用（`comic_checker/wikipedia_client.py:147-150`）

```python
COMPLETED_WEAK_RE = re.compile(
    r"連載(?:が|を)?終了(?:した)?|連載された|まで[^。、]{0,20}?連載(?:された)?|打ち切(?:り|られ)"
    r"|配信された"
)
```

### 事前確認: 実データのE_missed文が既存パターンで本当に不一致か（実測）

| タイトル | 実際の文（抽出、実測） | `COMPLETED_WEAK_RE.search()`結果（実測） |
|---|---|---|
| 砲神エグザクソン | 「講談社の「月刊アフタヌーン」で連載され、アフタヌーンKCから全7巻の単行本が刊行された。」 | `None`（不一致） |
| 文豪の食彩 | 「『食漫』（日本文芸社）に連載され、連載時のタイトルは「文士のお取り寄せ」であった。」 | `None`（不一致） |

**両文とも「まで」を伴わないため、既存の`まで[^。、]{0,20}?連載(?:された)?`枝には
救われない**ことを実測で確認した。したがって、Issue #157の取りこぼしは本物であり、
新しいパターンの追加が必要という前提は成立している。

### 変更案（複数案を列挙し、事前登録の対象を明示）

**案1（単純追加、Issue #157が「素朴」と呼ぶもの）**:

**本事前登録が主たる検証対象とするのは案1**。ただし3節で述べる個別確認計画が
P2（同一文内競合）で不合格となった場合、案2の設計検討に進む必要がある。

#### P1の反証（4節末尾の予測本体で実施、削除禁止の記録）

**当初の懸念**（1節・上記引用のとおり）は、`step98_b_issue_drafts.md`が
「未検証の手作業シミュレーション」（`corpus_expansion_design.md`55-56行目が
自ら明記）によって発見したものだった。

**反証の根拠（実測）**: 実装の`_is_novel_primary()`・`MANGA_MARKERS`・
`NOVEL_MARKERS`を直接importして、最強職《竜騎士》の新規一致文「2017年7月から
『小説家になろう』にて連載され、2018年1月から書籍版がガガガブックス（小学館）
より刊行されている。」を含む全8文をトレースした。

- `wc._is_novel_primary(extract)`実測: `True`（`is_multimedia=True`）。
- 当該文自体の`has_manga`（`MANGA_MARKERS`該当語の有無）: **無し**。
  `has_novel`（`NOVEL_MARKERS`該当語の有無）: **有り**（「小説家になろう」が
  「小説」を部分文字列として含む）。
- `_judge_extract()`699-702行目のゲート条件`has_manga and not has_novel`は
  `False`となり、**この文では返らない**。
- 全8文中、`has_manga=True`となる文はindex4「メディアミックスとして、
  「マンガワン」にてコミカライズ版が連載開始、作画は幸路。」の1文のみだが、
  この文自体は`COMPLETED_WEAK_RE`（現行・案1いずれも）にも`ONGOING_RE`にも
  一致しないため決着しない。
- 他の全文でも`weak_completed`/`ongoing`のいずれも発生しない。
- **結論: 案1適用後もこの行はSTATUS_UNKNOWN（判定不能）のまま変化しない。**

**旧懸念が誤りだった原因**: `step98_b_issue_drafts.md`の手作業シミュレーションは
`judge()`本体が実際に持つ`is_multimedia`/`MANGA_MARKERS`ゲート（`_judge_extract()`
699-709行目）を反映せずに「連載され、が新規一致すれば即座に完結になる」と
判定していた。これは`verification_procedure.md`手順1が禁じる「サブ関数だけを
個別に呼び出すシミュレーション（judge()本体のveto層・ゲート層を見落とす）」の
実例にあたる。

**したがってP1は、事前登録の合否基準（6節条件1）としては引き続き残すが
（安全側の担保として)、今回の静的予測の結果からは「実行しても不合格になる
見込みは低い」という位置づけになる。** 実judge()での確認（実行フェーズ）を
省略してよいという意味ではない——静的予測はあくまで予測であり、6節条件1の
最終判定は実judge()ハーネスでの再確認を経て行う。

### P2（デュエル・マスターズ型: 同一文内tie競合による取り違え）

`comic_checker/wikipedia_client.py:153-166`のコメントが記録する既知の近接事例
（Issue #134の設計時にホールドアウトとして扱われた実例、現行160行コーパスには
不在）を出発点に、事前登録作成時に新たに発見したリスク。

**発見内容（実測）**: 「連載され、」を含み、かつ同一文内にONGOING_RE一致語
（例:「連載されている」）も含む文で、`MIGRATION_SAME_SENTENCE_RE`が対応する
接続語（のち／その後／後）を使わない構文の場合、案1適用後は`weak_completed=True`
かつ`ongoing=True`の同一文内tieが発生し、`_judge_extract()`686行目付近の
`if ongoing == completed: continue`によりその文が**無条件にスキップされる**。

合成文での実測（`comic_checker/wikipedia_client.py`は無改変）:

```python
sentence = "2002年より『月刊コロコロコミック』にて連載され、同年5月1日よりウェブでも連載されている。"
# COMPLETED_WEAK_RE_案1.search(sentence) -> match '連載され、'
# ONGOING_RE.search(sentence)            -> match '連載されている'
```

**命題**: 案1を適用した場合、現行コーパス160行＋`tests/`内の実データフィクスチャの
全行のうち、この同一文内tie（新たに`weak_completed`と`ongoing`が両方Trueになる文）
が発生し、かつその結果その文がスキップされたことで**行全体の最終statusが変化する
（悪化する）行が1件も無い**（tieが発生しても、他の文で正しく決着する場合は無害
なため、「行全体のstatusへの影響」を基準にする）。

**手順（addendum反映、After版）**: P1と同一の実judge()比較手順を、そのまま流用する
（`run_judge_with_snapshot()`を修正前後でプロセス内属性差し替えして呼び、
`status`/`evidence`を比較する。**ハーネスの改変は不要**——P2の命題は行レベルの
最終status変化の有無であり、文単位の内部観測を必要としない）。

P1・P2は同一の実行1回分の比較結果から同時に判定できる。すなわち、修正後に
statusが変化した行のうち、期待ラベルが「連載中」または「判定不能」なのに
「完結」になった行がP1の不合格条件、期待ラベルが「連載中」だったのに
`_judge_extract()`が判定不能・別status化してしまった行（同一文内tieによる
スキップが原因と推測される、evidence文の変化から間接的に確認できる）が
P2の不合格条件にあたる。

原因がtieであることの特定（診断であり合否判定そのものではない）が必要な場合は、
該当行のextractに対し`re`モジュールで`COMPLETED_WEAK_RE`（案1）と`ONGOING_RE`の
共起を機械的に走査する（判定手段としてではなく、候補特定の位置づけ。4節の
影響予測手順と同じ扱い）。

**翻訳できたか**: できた。ハーネス改変は不要と判明した
（`prereg_lineage3_addendum_feasibility.md`2節で確認済み。旧版が書いていた
「既存のハーネスにログ出力が無ければ追加が必要」という記述は過剰要求であり、
訂正済み）。

## 4. 影響予測（実行前の宣言）

### フィクスチャ範囲の確定（addendum反映、閾値10採用）

**フィクスチャ範囲は`ast`モジュールによる構文解析（grepではなく。複数行文字列・
代入形式の揺れを取りこぼさないため）で定義する。** 列挙定義（カテゴリA/B/C）は
`~/comic_checker-agent-notes/tmp_enumerate_test_extracts.py`参照。

**閾値は10文字を採用する**（ユーザ決定）。理由: 予測範囲は広い方が保守的であり、
余分な行を「変化なし」と予測しても害がないため。

| カテゴリ | 定義 | 件数（閾値10） |
|---|---|---|
| A | モジュールレベル`*_EXTRACT`定数、文字列リテラルのみ | 48 |
| B | 関数内ローカル、代入先名に`extract`含む／日本語文字を含み長さ閾値以上 | 11 |
| C | `judge`/`_judge_extract`/`_judge_via_infobox`への直接文字列引数、日本語文字を含み長さ閾値以上 | 4 |
| **合計** | | **63** |

閾値20・30の集合は63件（閾値10）の部分集合である（閾値20→48+10+1=59件、
閾値30→48+9+0=57件）。閾値境界で脱落する6件（10→20で1件、20→30で1件、
カテゴリC側10→20で3件・20→30で1件）は実測ですべて確認したところ、
**いずれも「連載され」を含まず、系統3の変更と無関係**（作品タイトル・
巻数文字列のみ）だった。したがって閾値10採用による過剰包含は無害である。

案Bの「48定数＋関数内ローカル4件＝52件」とは直接比較できない（案Bの
「ローカル4件」を導出したコマンドが記録から復元不能だったため。
`prereg_lineage3_addendum_feasibility.md`4節「記録欠陥の指摘」参照）。
本文書の63件（閾値10）を新たな基準として採用する。

**予測対象**: 保存コーパス160件（holdout99+regression61）＋`tests/`内の
実データフィクスチャ63件（閾値10）、計223件。

**「検出が変わると予測する記事」の特定手順**:
1. 各対象の`extract`を`_split_sentences()`（実装からimport）で文分割する。
2. 各文に対し、案1のパターンが新たに一致するかを機械的に判定する
   （このスクリプト内のローカル変数として`re.compile()`するのみ、`comic_checker`
   のモジュール属性には代入しない）。
3. 新規一致する文を含む対象について、`ONGOING_RE`・`COMPLETED_STRONG_RE`・
   `MIGRATION_SAME_SENTENCE_RE`・`SPINOFF_MARKERS`・`_is_novel_primary()`・
   `MANGA_MARKERS`/`NOVEL_MARKERS`という実装の純粋関数・定数を直接使って
   個別にトレースし、status変化を予測する。
4. `_judge_extract()`・`judge()`本体は一切呼ばない（サブ関数個別呼び出し
   シミュレーションの厳禁に抵触しないよう、ループ構造は模倣せず、分類結果を
   人間が個別にトレースする）。

**影響件数の基準**: `prereg_v2_effective_count_basis.md`の「最低2件」を踏襲する。

### `ambiguous_extract`（L2240）の流用不適について（4節・addendum反映）

`ambiguous_extract`（`test_judge_does_not_let_infobox_declare_completed_
against_prose_ongoing_signal`関数内）は、当初「P2の同一文内tie型ミューテーション

**流用不適と判明した**。

**理由（実測）**: この文「『週刊サンプルA』にて2017年から2023年まで連載され、
移籍先でも同年より連載中。」は、**現行`COMPLETED_WEAK_RE`が既に「まで連載」枝で
一致している**（`まで[^。、]{0,20}?連載(?:された)?`枝が「まで連載」の部分で
一致、実測span(23,27)）。同一文内で`ONGOING_RE`（「連載中」）も一致するため、
**このフィクスチャは案1導入前から既にtie状態にあり、`STATUS_UNKNOWN`という
テストのアサーションも既存の「まで」枝のみで成立している**。案1（「連載され、」
追加）はこの文に対して完全に冗長であり、案1固有の判別力を実証する証拠には
ならない。

**したがって、P2のミューテーションテストには「まで」を含まない新規の合成
フィクスチャの設計が必要である。** 具体的な合成文（例:「まで」を使わず

残す**（5節冒頭の代替語候補の到達性確認と合わせて、実行時に設計する）。
