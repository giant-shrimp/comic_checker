# 事前登録追補: 案Bミューテーションテストの合成フィクスチャ再設計

**作成日**: 2026-08-16
**位置づけ**: `docs/code_defects_2026-08/prereg_planb_safety_verification.md`
（案Bの安全性検証の事前登録本体）への追補。**本体は書き換えない**（3節の
変化予測を含め、既存の記述は一切変更しない）。

**この追補は検証実行前に確定させたものである。** 合成フィクスチャの実行
（`_has_ongoing_signal()`を実際に呼び出して5節の期待結果と突き合わせること）は、
本追補を含むPRがマージされた後に行う。本文書自体には実行結果を含めない。

## 1. 追補の理由

`docs/code_defects_2026-08/planb_verification_result.md`が記録したとおり、当初の
ミューテーションテスト（代替語「コミカライズ」）は実`judge()`で0件となり、
`verification_procedure.md`手順5の規定（「0件なら検証系の欠陥として扱い、
報告して停止する」）に該当した。代替語の再選定を試みたが、
`docs/code_defects_2026-08/mutation_candidate_search_result.md`が記録したとおり、
選定基準（MANGA_MARKERS非該当・SPINOFF_MARKERS非該当・`_has_ongoing_signal()`
自身への到達・`is_multimedia=True`限定）を満たす代替語は現コーパスに1つも
存在しなかった。

したがって、実データの代替語によるミューテーションテストは断念し、**合成
フィクスチャによる`_has_ongoing_signal()`単体のミューテーションテスト**に
切り替える。`_has_ongoing_signal()`はextractの文字列に対する正規表現判定であり、
合成文でもこの関数単体の機構検証は成立する（過去に合成が不可とされたのは
`_infobox_has_field()`のwikitext構造の再現であり、これとは別の問題である）。

## 2. 合成フィクスチャの設計

`SPINOFF_MARKERS`の5要素（続編・番外編・スピンオフ・外伝・次世代編）それぞれに
ついて、**単一の文からなるextract**を用意する。各文は、その要素タグを含み、
かつ`ONGOING_RE`（「連載中」または「連載されている」）に一致する。extractが
単一文のみであるため、除外が働けば`_has_ongoing_signal()`は走査対象の文が
無くなり`False`を、働かなければ`True`を返す（`any()`の性質上、空集合に対しては
`False`になる）。

| 要素 | 合成文 |
|---|---|
| 続編 | `続編『二代目主人公』が『月刊なんとか』にて連載中。` |
| 番外編 | `番外編『裏エピソード』が『月刊なんとか』にて連載中。` |
| スピンオフ | `スピンオフ『外伝物語』が『月刊なんとか』にて連載中。` |
| 外伝 | `外伝『裏話』が『月刊なんとか』にて連載中。` |
| 次世代編 | `次世代編『新世代』が『月刊なんとか』にて連載中。` |

いずれも「マーカー語＋固有名詞＋『にて連載中。』」という同一構造で統一し、
マーカー語以外の要因（文の長さ・語順・句読点の位置等）が結果に影響しないよう
にした。

## 3. 負のコントロール（省略不可）

`SPINOFF_MARKERS`に含まれない語を用いた合成文を用意し、除外の有無にかかわらず
`_has_ongoing_signal()`の戻り値が変わらないことを確認する。これが無いと、
「除外機構が常に`False`を返しているだけ」という壊れ方と、「特定のマーカーだけを
正しく除外している」という正しい挙動を区別できない。

- **負のコントロール文**: `リメイク版『新装版』が『月刊なんとか』にて連載中。`
- **選定理由**: 「リメイク」は`SPINOFF_MARKERS`（続編・番外編・スピンオフ・
  外伝・次世代編）にも`MANGA_MARKERS`にも含まれない、5要素の合成文と同じ
  「マーカー語＋固有名詞＋『にて連載中。』」構造の文。除外対象に該当しないため、
  修正前後で`_has_ongoing_signal()`の戻り値が変化しないことを確認する。

## 4. 各要素が観測可能な差を生むことの確認方法

CLAUDE.mdが定める「複数ガードが同じ値を返す場合、一つを除去しても出力が
変わらない」問題を避けるため、5要素を**まとめて1つの合成文でテストせず、
要素ごとに独立したextract（1要素1文）で個別にテストする**設計にした。これにより:

- 5要素のうちどれか1つが（例えば将来のリグレッションで）`SPINOFF_MARKERS`から
  外れた場合、**その要素のextractだけ**が「除外前後で戻り値が変わらない
  （`True`のまま）」という形で検知でき、他の4要素のテストの合否には影響しない。
  5要素を1つの文にまとめていた場合、いずれか1要素が機能しなくなっても、
  他の要素が拾うため合否判定上は「合格」のまま埋もれてしまう
  （まさに「複数ガードが同じ値を返す」問題）。
- 各extractが単一文のみで構成されているため、「どの文が効いたか」の曖昧さが
  無い（複数文からなる合成フィクスチャでは、期待どおりの文以外が偶然決着に
  寄与する可能性を排除しきれない）。

## 5. 期待される結果の事前確定（実行後に書き換えない）

| フィクスチャ | 修正前（`_has_ongoing_signal()`未修正） | 修正後（案B適用） |
|---|---|---|
| 続編 | `True` | `False` |
| 番外編 | `True` | `False` |
| スピンオフ | `True` | `False` |
| 外伝 | `True` | `False` |
| 次世代編 | `True` | `False` |
| 負のコントロール（リメイク） | `True` | `True`（変化なし） |

**合格の基準**: 5要素すべてで`True→False`の変化が観測され、かつ負のコントロールで
戻り値が変化しないこと。5要素のいずれか1つでも`True→False`にならなかった場合、
または負のコントロールが変化した場合は、実装（1-1節の差分）が5要素すべてを
正しく除外できていない、または除外が過剰であることを意味し、その旨をそのまま
報告する（自力で修正・再設計しない）。

## 限界の記述（省略不可、薄めて書かない）

- **合成文による確認は「機構が動作すること」を示すのみで、「実データで意味のある
  効果があること」は示さない。** 後者（実データでの効果）の根拠は、主検証
  （`planb_verification_result.md`）が実データで得た2件（バーテンダー à Tokyo・
  陰陽師）のみである。この2件はいずれも「続編」によるものであり、残る4要素
  （番外編・スピンオフ・外伝・次世代編）については、実データでの効果は主検証でも
  今回の合成フィクスチャでも確認できていない。
- **番外編・外伝・次世代編については、現コーパスにONGOING_REと共起する文が
  1件も無く（`effective_hit_rate_analysis.md`実測）、実データでの効果は今回も
  今後も現コーパスでは確認できない。** 合成文でこの3要素についても機構自体が
  「除外という動作をする」ことは確認できるが、それが実際の記事でどう振る舞うか
  （誤って必要な情報を除外してしまわないか等）は未検証のまま残る。
- **合成文は作成者（本セッションのAI）が「効くように」書けてしまうため、実データ
  より弱い証拠である。** 本追補の5節の合成文は、いずれも`_has_ongoing_signal()`の
  除外条件（`marker in sentence`という単純な部分一致）が確実にヒットするよう、
  意図的に単純な構造（マーカー語を含む短い1文のみ）で構成している。実際の
  Wikipedia記事の文はこれよりはるかに複雑（長い修飾節・複数の固有名詞・
  他のマーカーとの共起等）であり、合成文で機構が動作することが、実データの
  多様な文構造でも同様に動作することを保証しない。
