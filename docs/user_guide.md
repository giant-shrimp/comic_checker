# コミックチェッカー 利用ガイド

Python などの準備は不要です。配布された `comic_checker.exe` をダブルクリックするだけで
使えます。このガイドは、そのアプリを使う方に向けたものです（開発する方向けの情報は
[README.md](../README.md) を参照）。

## これは何をするもの？

Excel に並んだ漫画タイトルの一覧を読み取り、それぞれが **完結**しているか
**連載中**かを日本語 Wikipedia で調べて、結果を同じ Excel に書き戻すアプリです。

- インターネットに接続していれば動きます。
- 調べた結果は、元の Excel ファイルに列を足す形で書き込まれます。
- 100 件でも 1000 件でも、一覧をまとめて自動でチェックできます。

## 1. アプリを受け取る

### GitHub のアクセス権がある場合（推奨）

[Releases ページ](https://github.com/giant-shrimp/comic_checker/releases)から
最新版をダウンロードできます。

1. 上記ページを開く（一番上が最新版）
2. 「Assets」を開き、`comic_checker.exe` をクリックしてダウンロードする
3. ダウンロードした `.exe` ファイルを、デスクトップや任意のフォルダに置く

**インストール作業はありません。** ダウンロードしたファイルをそのまま使えます。

> このリポジトリは非公開（private）のため、Releases ページを開くには GitHub
> アカウントでこのリポジトリへのアクセス権が必要です。「ページが見つかりません」
> と表示される場合は、次の「GitHub のアクセス権が無い場合」を参照してください。

### GitHub のアクセス権が無い場合

`comic_checker.exe` を渡してくれた開発者から直接受け取ってください（社内共有
フォルダ、USB メモリ、ファイル転送など、渡し方は問いません）。受け取った `.exe`
ファイルを、デスクトップや任意のフォルダに置けば準備完了です。

> このアプリは 1 つの `.exe` ファイルだけで動きます。フォルダごと配られた場合も、
> 中の `comic_checker.exe` をそのまま使えます。

## 2. 起動する（SmartScreen 警告への対処）

`comic_checker.exe` をダブルクリックします。

初回起動時、Windows が青い画面で

> **Windows によって PC が保護されました**
> Microsoft Defender SmartScreen は認識されないアプリの起動を停止しました。

と表示することがあります。これは「発行元の署名が付いていない配布ファイル」に対して
Windows が出す**標準的な警告**で、アプリが壊れているわけではありません。次の手順で
起動できます。

1. 警告画面の **「詳細情報」** をクリックする
2. 下に現れる **「実行」** ボタンをクリックする

一度実行すれば、次回以降は警告なく起動できることが多いです。

> 警告が出ること自体は想定内です（このアプリはコード署名をしていないため）。
> どうしても不安な場合は、渡してくれた開発者にファイルが正しいものか確認してください。

## 3. Excel を準備する

チェックしたいタイトルの一覧を Excel（`.xlsx` 形式）で用意します。

- **1 行目を見出し行にし、タイトルを入れる列の見出しを「タイトル」にしてください。**
- タイトルは 1 行に 1 作品ずつ入れます。

例：

| タイトル |
|---|
| ONE PIECE |
| 進撃の巨人 |
| ダンダダン |

見出しが「タイトル」でない（例：「作品名」）場合は、そのままでは読み取れません。
見出しを「タイトル」に変えるか、開発者に相談してください。

> **開いたままだと保存できません。** アプリは処理の最後にこの Excel へ書き込みます。
> 対象の Excel ファイルは、実行前に閉じておいてください（Excel で開いたままだと、
> ファイルがロックされて保存に失敗します）。

## 4. 使う

1. アプリの上部「📁 対象ファイル」で、チェックしたい Excel を指定します。方法は 2 通り：
   - **「ファイルを選択…」ボタン**を押して選ぶ
   - ファイルを枠に**ドラッグ＆ドロップ**する（「ここに .xlsx をドラッグ＆ドロップ
     できます」と出ている場合）
2. **「▶ 実行」ボタン**を押します。
3. 「📊 進捗」欄で、進捗バーと `処理中… 3/10 件` のような表示が進みます。
4. 「📝 ログ」欄に、1 件ごとの結果（`[1/10] ONE PIECE -> 連載中 …`）が流れます。
5. 終わると「内訳」に **完結／連載中** などの件数がまとまって表示され、進捗バーが
   緑色になります。

処理が終わると、結果は**元の Excel ファイルに保存済み**です。Excel を開いて確認して
ください。

> - `.xlsx` 以外のファイルをドロップした場合は、ログにメッセージが出るだけで、
>   選択は変わりません（間違ったファイルで上書きされることはありません）。
> - 途中まで進んだところで閉じてしまっても、一定件数ごとに保存されるため、
>   そこまでの結果は残っています。

### 同じファイルをもう一度実行したとき

**すでに結果が入っている行は、既定では飛ばします。** 途中で閉じてしまった続きから
再開できるようにするためです。

そのため、**すでに全部の行を調べ終えたファイルをもう一度実行すると、調べる対象が
0 件になります。** この場合、実行前に次の確認画面が出ます。

> **判定済みの行があります**
> このファイルには 73 行中 73 行に判定結果が入っています。
> このまま実行すると、処理対象は 0 件になります（すべての行が判定済みのため
> スキップされます）。
> 判定結果を最新の内容に更新したい場合は、すべて再判定してください。

ボタンは 3 つです。

- **判定済みをスキップして実行** … これまでどおり、未判定の行だけを調べます
  （Enter キーでも選べます）。全部が判定済みなら、調べる対象は 0 件です。
- **すべて再判定する** … 判定済みの行も含めて、**全部を調べ直します**。前回の結果は
  新しい結果で上書きされます。手で直した内容も消えるのでご注意ください。
- **キャンセル** … 実行しません（Esc キーでも選べます）。

一部だけ判定済みの場合も同じ確認画面が出て、「未判定の 5 行だけを処理します」の
ように、実際に調べる件数が表示されます。

> **アプリを新しい版に入れ替えたときは「すべて再判定する」を選んでください。**
> 判定の精度は版によって改善されることがありますが、既存の結果が入ったままでは
> 新しい判定が反映されません。

## 5. 結果の見方

実行すると、Excel に次の列が（無ければ）追加され、結果が書き込まれます。

| 列名 | 内容 |
|---|---|
| 連載状況 | 判定結果。下の表を参照 |
| 判定方法 | どこで調べたか（通常は `Wikipedia`） |
| 判定根拠 | そう判定した根拠になった Wikipedia の一文 |
| 参照タイトル | 実際に参照した Wikipedia 記事のタイトル（合っているか確認用） |
| 参照URL | 参照した Wikipedia ページの URL |

「連載状況」に入る値の意味：

| 値 | 意味 |
|---|---|
| **完結** | 作品が完結している（打ち切りを含む。詳しくは「判定根拠」列を参照） |
| **連載中** | 現在も連載が続いている |
| **判定不能** | Wikipedia は見つかったが、完結か連載中かを確信を持って判定できなかった |
| **記事なし** | 日本語版 Wikipedia にその作品の記事が無かった |
| **エラー** | その行の処理中に問題が起きた（次の行の処理は続行される） |

> **「記事なし」の多くは、アプリの失敗ではなく「本当に記事が無い」という結果です。**
> 日本語版 Wikipedia は、すべての漫画に記事があるわけではありません。短期で終わった
> 作品、青年誌・成人向けの作品、アンソロジーなどは、記事そのものが作られていないことが
> よくあります。実際の一覧で試したところ、「記事なし」になった行はほぼすべてが
> 「Wikipedia に記事が存在しない作品」でした。
>
> 「記事なし」が多くても、まずは異常ではないとお考えください。気になる行は「参照URL」が
> 空になっているので、ご自身で Wikipedia を検索して記事の有無を確かめられます。

**「参照タイトル」列は必ず確認することをおすすめします。** 入力したタイトルと違う記事が
参照されていることがあり、その場合その行の判定は当てになりません。よくあるのは次の
3 パターンです。

- **別作品の記事** … 同名・似た名前の別作品にヒットした場合。判定は無関係な作品のものです。
- **シリーズ全体の記事** … 「〇〇　青版」のように版を指定して書いた場合、版ごとの記事が
  無いため、シリーズ全体の記事で判定することがあります。シリーズは続いていても、
  その版だけ刊行が止まっていることがあります。
- **原作・親作品の記事** … スピンオフ作品に単独記事が無い場合、原作側の記事で判定する
  ことがあります。原作が連載中でも、スピンオフは終わっていることがあります。

いずれも、参照タイトルが入力したタイトルと違っていれば気づけます。**入力したタイトルと
参照タイトルが一致している行は、そのまま信頼して構いません。**

> **「判定不能」は間違いではありません。** 原作小説とコミカライズが別々に存在する
> 作品などで、「その状況説明が漫画の話なのか原作小説の話なのか確信できない」ときに、
> 無理に決めつけず「判定不能」としています。手動で確認してください。

## 6. 困ったときは（トラブルシューティング）

### ダブルクリックしても何も起きない／すぐ消える

- ウイルス対策ソフトがブロックしている可能性があります。「2. 起動する」の SmartScreen
  対処を試してください。それでも起動しない場合は、ウイルス対策ソフトの検疫
  （隔離）フォルダに入っていないか確認してください。
- ネットワークの制限が厳しい環境では、起動はしても Wikipedia に接続できず、結果が
  すべて「記事なし」や「エラー」になることがあります。

### 「実行」を押しても「Excelファイルを選択してください」と出る

- 先に「📁 対象ファイル」でファイルを指定してください（未選択の状態では実行できません）。

### 実行するとエラーになる／すべて「エラー」になる

- 対象の **Excel ファイルを閉じてから**実行してください（開いたままだと保存に失敗
  します）。
- Excel の 1 行目の見出しに **「タイトル」列があるか**確認してください。無いと
  タイトルを読み取れません。
- インターネットに接続されているか確認してください。

### 「実行」を押したのに何も起きない／「処理対象の行がありません」と出る

- そのファイルの行がすべて調べ終わっている状態です。「4. 使う」の
  **「同じファイルをもう一度実行したとき」** を参照してください。確認画面で
  **「すべて再判定する」** を選ぶと、全部を調べ直せます。

### 「判定不能」や「記事なし」が多い

- **記事なし**：まず「5. 結果の見方」の注記を確認してください。**その作品が日本語版
  Wikipedia に載っていないだけ**であることがほとんどです。全角・半角の違い、書名に
  付けた `（特装版がない場合通常版）` のようなメモ書き、`　青版` のような版の表記は
  アプリ側で自動的に読み替えるので、これらを手で直す必要はありません。
- **判定不能**：原作と漫画が別々にある作品などで起きやすい判定です。「判定根拠」列と
  「参照URL」列を手がかりに、手動で確認してください。
- **前の版のアプリで調べた結果が残っている場合**：判定の精度は版によって改善されて
  いることがあります。確認画面で「すべて再判定する」を選び、調べ直してみてください。

### 文字が □ や豆腐のように表示される

- 日本語フォントや絵文字が用意されていない環境で起こることがありますが、動作自体には
  影響しません。見出しのアイコンが出ないだけで、機能はそのまま使えます。

### ドラッグ＆ドロップができない

- 「ファイルを選択…」ボタンからの選択は常に使えます。そちらをお使いください
  （ドラッグ＆ドロップは環境によって使えないことがあります）。

### 自分が使っているバージョンを確認したい

ウィンドウのタイトルバー、またはログ欄の下にある「バージョン: …」の表示で確認できます。

### 新しい版が出ているか確認したい

GitHub のアクセス権がある場合は、
[Releases ページ](https://github.com/giant-shrimp/comic_checker/releases)の
一番上（最新版）に表示されているバージョンと、自分が使っている版（上記の
「バージョン: …」表示）を見比べてください。新しい版があれば、「1. アプリを
受け取る」と同じ手順でダウンロードし直してください。

アクセス権が無い場合は、渡してくれた開発者に確認してください。

---

上記で解決しない場合は、**ログ欄に表示されている内容**を控えて、渡してくれた開発者に
共有してください。どの行で何が起きたかが分かると、原因の切り分けが早くなります。
**その際、上記の「バージョン: …」の表示もあわせて伝えてください。** 版によって挙動が
異なることがあり、どの版で起きた問題かが分かると、原因の切り分けが早くなります。
