## 4. 起きた問題と知見

- 報告の行番号の誤り：上流1では、4節・ask 対象の段落・5節の行番号をずらして書いた。全文の確定では、sed -n の出力の先頭と末尾の空行を書き写さず、ask 対象の段落の行番号も誤った。行番号は cat -n で確かめる。
- 1回の応答で複数のツール呼び出しを2回出した（照合の6つ、verify.sh と grep の2つ）。どちらも読み取りか /tmp への書き出しだけだった。次の段取りから指示に「前回これに違反した」と添えると、起きなかった。
- git log の --format をクォートせずに構文エラーになり、1回だけ実行し直した。
- 照合の弱点：`printf '%s' "$(cat …)"` の sha256 は末尾の改行を除いて計算するので、Web 編集で末尾の改行が落ちても一致する。落ちたことは wc -l の行数で分かる。改めた手順4は sha256 と行数の両方を照合するので、文面には足さなかった。
- review は、deny 対象の手順5でローカルの verify.sh と pre-push-check を省くことが CLAUDE.md の作業ルールの例外になる点を、ADR か docs/ に残すよう提案した。#441 から同じ運用で、CI の verify が PR ごとに走るので、対応せず、別の Issue の候補にもしなかった。
- 承認画面が出た回数と、cp・push 以外の操作で出たかは記録していない。
- 実装役の実績：ツール呼び出し38回・約62秒（起動は1回）。
