## 4. 起きた問題と知見

- ask 対象への cp で承認画面が出なかった。AskUserQuestion は出たが、実装役の cp では承認画面が出ずに反映された。一方、push では `.claude/settings.local.json` の `Bash(git push *)` の ask で承認画面が出た。
- 司令塔の調査（読み取りのみ）によると、公式文書（permissions）は Edit のパス規則が Bash の cp に及ぶとは書いておらず、Write(path) の規則は参照されないとしている。auto モードでも、Bash の内容つきの ask 規則は確認を求めると書かれている。これまで（#417・#427・#429・#435）承認画面が出ていた理由は確かめていない（版の変化、当時の権限モード、汎用の cp が allow にないことによる通常の確認などが候補）。
- このため、commander 4節・ADR-035・`.claude/settings.json` 5行目の注記にある「反映の直前に承認画面が出る」は、Bash の cp による反映には当てはまらない可能性がある。今回は、AskUserQuestion で同意を得た確定版と sha256 が一致していたので、そのまま進めた。
- 指示の誤り：実装役への依頼文に「承認画面が出ないまま cp が通った場合は止める」を入れた。承認画面は実装役からは見えないので、実装役は確かめられずに止まった。止める条件には、実装役が観測できること（エラー・拒否・sha256 の不一致）を使う。
- 実装役の再開に SendMessage を使った。commander は実装役を Agent ツールで呼ぶ前提で書かれているが、文脈を保ったまま再開でき、問題はなかった。
- 実装役の実績：1回目はツール呼び出し6回・約14秒、再開後は26回・約48秒（累計かどうかは不明）。
