## 3. 機能したこと

- E6：上流1の Issue の案に「変更後の全文を誰が書くか」が入り、文書の完了条件が grep・wc・git diff の値で定められた。
- 変更後の全文を Issue より先に確定したことで、完了条件を「以上」ではなく一致の値（sha256・行数・numstat・grep の件数）で書けた。
- 実装役は依頼どおり既存ファイルへの cp で反映し、ファイルのモードを保った。
- E5 は対象が ask 対象でないため使わなかった。E1・E7 は CI と実装役が止まらなかったため使う場面がなかった。

## 4. 起きた問題と知見

- 上流1の自己点検で、走査器の終了コードを見るために `;` で echo をつないだ。読み取りだけで影響はなかった。以後「echo をつなぐことも行わない」と明記し、守られた。
- /tmp に書き出した確定版はモードが 100644 になった（元は 100755）。既存ファイルへの cp ではモードが変わらないので、完了条件に `git diff --summary` が空であることを加えた。
- 指示の想定値の誤り：ファイル名を渡す sha256sum の値の一致と、取得した本文の行数が1多いことを、同時に想定していた。`printf '%s' "$(cat <ファイル>)" | sha256sum` の形で比べれば一致する。
- 指示の方針の文言の誤り：「ADR-034 の未決定事項」としたが、ADR-034 の未決定の節にこの件はなく、未決定としていたのは試走の記録だった。司令塔が事実に合わせて書いた。
- 「GraphQL 経由の gh を使わない」は、リポジトリのファイルに書かれた規則ではなく、指示の記載規則にある。runbook には運用の事実として書いた。
- 後始末の `git fetch --prune` が SSH の公開鍵認証の失敗で止まった。直前の `git pull` は成功しており、再実行で通った。原因は確かめていない。リモートブランチの状態は gh api の branches（404 なら削除済み）でも確かめられる。
