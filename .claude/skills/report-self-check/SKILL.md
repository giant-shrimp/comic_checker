# 報告前の自己点検

comic_checker では，報告本文に個人情報・実在作品名が紛れ込む事故が繰り返し
起きている（背景）．このスキルは，報告を送る**直前**に，下書きを機械的に
検査する．

## 背景（ERRORS.md）

`docs/errors_md_inventory.md` の No.50・51・54・60・63・65〜73（いずれも本文は
ここに転記しない．必要であれば該当Noを`ERRORS.md`で直接確認する）．

## 手順1: 下書きをファイルに書き出す

報告の下書き全文を `/tmp/report_draft.md` に書き出す．要約・省略はせず，
実際に送るつもりの本文をそのまま書く．

## 手順2: 2つの走査器を実行する

リポジトリのルートで次の2つを実行する．

```bash
python3 scripts/check_no_personal_info.py /tmp/report_draft.md
python3 scripts/check_title_leak.py /tmp/report_draft.md
```

どちらも終了コード0になるまで下書きを直して繰り返す．`check_title_leak.py`
が警告（2〜3文字の一致）を出した行は，その一致が実在作品名の一部として
書かれていないかを確認する（警告だけでは終了コードは0のままなので，
機械的には止まらない．必ず目で見て判断する）．

## 手順3: 機械で検出できない項目のチェックリスト

下書きを読み直し，次のすべてを確認する．1つでも該当すれば直してから
手順2に戻る．

- コミットの Author・committer 行を貼っていない
- 棚卸し表の見出し列の値を貼っていない
- `git diff` の削除行に作品名・個人名が残っていない
- 伏せ字と置き換え前の対応表・凡例を併記していない
- Issue・ADR・測定結果の要約に作品名を書いていない
- ツールの自動出力（pytest のヘッダ，一時ディレクトリのパス等）を無加工で
  貼っていない
- 「全文書き写す」指示より記載規則を優先した
- 記載規則に該当するかを「該当しないと確認した」と自分で正当化して
  掲載していない

## 手順4: 自己点検の明示

報告の末尾に次の形式で1行だけ付ける．

```
自己点検：走査器 exit X・作品名照合 exit Y（警告 Z 件）
```

X は `check_no_personal_info.py` の終了コード，Y は `check_title_leak.py` の
終了コード，Z はそのときの警告件数．いずれも手順2で実際に得た値を書く．

## 書いてはいけないもの

- 検出内容（作品名・行の本文）を報告に書かない
- スクリプトの標準エラー出力を報告に貼らない（貼ってよいのは手順4の1行だけ）
