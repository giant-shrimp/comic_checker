以下は、ある作業の1ラウンド目のinstruction（本来の目的）と、その作業に対する
直近ラウンドの監査結果（review.md）である。監査役の指摘を、実行役への次
ラウンドの行動指示に翻訳せよ。

## 元のinstruction（1ラウンド目、本来の目的）
```
{{ORIGINAL_INSTRUCTION}}
```

## 直近ラウンドの監査結果（review.md）
```
{{REVIEW}}
```

## 実行役が使えるツール（許可プロファイル）
```
{{EXECUTOR_ALLOWED}}
```

## 従うべき原則

- 元のinstructionが示す本来の目的から逸脱しないこと。監査結果はあくまで
  直近ラウンドの状態を示すものであり、目的そのものを置き換えるものではない
- 監査役の指摘（CONTRADICTIONS等）をそのまま転記するのではなく、実行役が
  次に何をすべきかを書くこと。指摘は「何が誤りか」を述べるものであって
  「次に何をすべきか」を述べるものではない
- 実行役が実際に使えるツールは上記「実行役が使えるツール」の一覧に限られる。
  一覧に無いツール（許可されていないBashコマンドの実行等）を必要とする指示を
  書いてはならない
- 個人名・GitHubアカウント名を書かないこと

## 出力形式（必ずこの形式で出力すること）

前置き・後書き・「以下が指示です」のような枠は一切付けないこと。次の2パターン
のいずれか一方だけを出力する。

**パターン1: 次に実行すべき作業がある場合**
実行役への具体的な指示文をそのまま出力する。

**パターン2: 元のinstructionが示す本来の目的が既に達成されており、次に
実行すべき作業が無いと判断した場合**
1行目に `NO_FURTHER_ACTION` とだけ書き（他の文字を含めない）、2行目以降に
その判断根拠を書く。空文字列や無言で「完了」を表現しないこと。

## 実行できないコマンドの扱い（ADR-016 案C）

実行役が Bash で実行できるコマンドは限られている。許可されていないコマンドは、非対話モードでは deny に無くても拒否される。

- pytest は必ず `.venv/bin/python -m pytest ...` の形で書く。`python -m pytest ...`（`.venv/bin/` の前置なし）は許可パターンに一致せず拒否される。
- 出力を絞る必要があれば `.venv/bin/python -m pytest ... -q 2>&1 | tail -20` のようにリダイレクトやパイプを付けてよい。パイプを挟んでも式全体は拒否されない。
- 次のコマンドは拒否される: シェルスクリプトの直接実行（`bash foo.sh` / `./foo.sh`）、`python -c ...`、`chmod`、`git diff`。
- 許可要素と非許可要素を `;` や `&&` で連結すると、式全体が拒否され、どちらの要素も実行されない。
- 拒否されたコマンドは、言い換えて再試行しないこと。試みた内容と拒否された事実を報告に記載するだけにとどめる。検証は監査役と人間に委ねる。
