# comic-checker

Excelに入っている漫画タイトル一覧を [Wikipedia](https://ja.wikipedia.org/)（日本語版）で
検索し、完結しているか連載中かを判定してExcelに書き戻すツールです。

もう1つの機能として、連載中の作品の次巻の発売日を楽天ブックス書籍検索APIで調べて、
Excelに書き込めます（[次巻発売日の確認](#次巻発売日の確認)）。完結チェックとは別の実行です。

> **配布された `comic_checker.exe` を使いたい方（Python 不要）** → まず
> **[利用ガイド（docs/user_guide.md）](docs/user_guide.md)** をご覧ください。
> ダブルクリックでの起動・SmartScreen 警告への対処・結果の見方・困ったときの対処を
> まとめています。以下の README は、ソースから動かす・開発する方向けの内容です。

WikipediaのMediaWiki APIにはCloudflare等のボット対策がなく、単純なHTTPアクセスで
利用できます。そのため完結チェックは既定では、ブラウザもAPIキーも不要です（次巻発売日の確認には楽天のキーが必要です）。Wikipediaで判定できな
かった行（判定不能・記事なし）だけ、`--fallback-to-manba` を付けた場合に限り
[manba.co.jp](https://manba.co.jp/) 経由での判定にフォールバックします（manba.co.jpは
Cloudflareのボット対策下にあるため、こちらはPlaywright（ヘッドレスブラウザ）で
実際にページを開いてアクセスします）。

## セットアップ

### 1. Python仮想環境の作成

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt   # 開発・テストする場合（フォールバック分も含む）
# または
pip install -r requirements.txt        # 実行のみ・Wikipedia経路だけで良い場合（軽量）
```

Wikipedia経由の判定のみを使う場合、セットアップはここまでで完了です（`requirements.txt`
には`playwright`を含めていない）。以下の2〜4は `--fallback-to-manba` を使う場合にのみ
必要です。`--fallback-to-manba`を使いたいが開発はしない場合は、代わりに
`pip install -r requirements-fallback.txt`（`playwright`を追加で含む）を使ってください。

### 2. （フォールバック使用時のみ）Playwright用Chromiumの取得

```bash
playwright install chromium
```

### 3. （フォールバック使用時のみ）OS依存ライブラリ

Chromiumの実行にはOSの共有ライブラリ（`libnspr4`, `libnss3`, `libatk1.0-0` など）が
必要です。以下のコマンドで確認・インストールできます（システムへの変更を伴うため、
実行するかはご自身で判断してください）。

```bash
playwright install-deps --dry-run chromium   # 何が足りないか確認するだけ
sudo playwright install-deps chromium         # 実際にaptでインストールする場合
```

### 4. （フォールバック使用時のみ）検索APIキーの設定

`--fallback-to-manba` を使う場合、manba.co.jpのキーワード検索ボックス（オートコンプリート）
が使っているのと同じ検索専用キーを使って、Meilisearchの検索APIを呼び出します。これは
manba.co.jpのフロントエンドで公開されている検索専用キーであり、サイトを訪れた誰の
ブラウザでも検索するたびに同じ値が使われている、秘匿情報ではないものです。それでも
READMEに固定値として書くとサイト側の変更で古い値のまま放置されやすいため、利用者
ご自身のブラウザで確認して設定する形にしています。

1. ブラウザでmanba.co.jpを開き、開発者ツールのNetworkタブを開く
2. 検索ボックスに何か入力する
3. `search.manba.co.jp/multi-search` へのリクエストを見つける
4. リクエストヘッダーの `authorization: Bearer ` の後ろの文字列をコピーする
5. 環境変数に設定する

```bash
export MANBA_SEARCH_API_KEY=<コピーした値>
```

### 5. （次巻発売日の確認を使う場合）楽天ブックスAPIのキー

[楽天ウェブサービス](https://webservice.rakuten.co.jp/)でアプリを登録し、アプリID（applicationId）とアクセスキー（accessKey）を取得してください。設定方法は次の2つで、キーごとに環境変数が優先されます。

1. 環境変数 `RAKUTEN_APP_ID`・`RAKUTEN_ACCESS_KEY` に設定する。
2. GUIの「設定」の画面（左のメニューの「設定」、またはメインの「楽天APIキーの設定…」ボタンから開く）で入力して保存する。保存先はWindowsなら `%APPDATA%\comic_checker\config.json`、それ以外なら `~/.config/comic_checker/config.json` です。

設定ファイルには暗号化せず平文で保存します（Windows以外では所有者だけが読める権限 0o600 にします）。キーの値はログ・画面・エラーの文面に出しません。

## 使い方

対象のExcelファイルの1行目にヘッダー行があり、タイトル列に「タイトル」という
列名がある前提です（列名は、コマンドラインでは引数で、GUIでは「設定」の画面で変更可能）。

```bash
source .venv/bin/activate
python -m comic_checker.main path/to/対象.xlsx
```

実行すると、以下の列が（無ければ）自動的に追加され、判定結果が書き込まれます。

| 列名 | 内容 |
|---|---|
| 連載状況 | `完結` / `連載中` / `判定不能` / `記事なし` / `ヒットなし` / `不明` / `エラー` |
| 判定方法 | 判定に使った情報源（`Wikipedia` / `manba.co.jp`） |
| 判定根拠 | Wikipedia判定時、根拠になったリード文の抜粋（manba.co.jp判定時は空） |
| 参照タイトル | 判定に使った記事・作品ページ上のタイトル（一致確認用） |
| 参照URL | 判定に使ったページのURL |

タイトルの表記ゆれなどで検索結果が別作品にヒットする場合があるため、
「参照タイトル」列で目視確認することを推奨します。「判定不能」は、原作小説と
コミカライズが併存する作品などで、判定文の主語（漫画か原作か）を確信できなかった
ことを意味します。無理に確定させていないだけなので、目視で確認してください。

### 主なオプション

```
--title-column        タイトル列のヘッダー名（デフォルト: タイトル）
--status-column        判定結果を書き込む列名（デフォルト: 連載状況）
--sheet                 対象シート名（省略時はアクティブシート）
--no-skip-filled        判定済みの行も再判定する（デフォルトは既判定行をスキップ）
--fallback-to-manba     Wikipediaで判定不能だった行をmanba.co.jp経由で判定し直す
                        （デフォルトは無効。有効時のみ以下のオプション・環境変数が必要）
--no-headless           （--fallback-to-manba時のみ）ブラウザを表示して実行する（動作確認用）
--min-delay / --max-delay  （--fallback-to-manba時のみ）リクエスト間の待機秒数（デフォルト 3〜6秒）
```

`python -m comic_checker.main --help` で全オプションを確認できます。

## 次巻発売日の確認

完結チェックとは別の実行で、各作品の次巻の発売日を調べてExcelに書き込みます。楽天ブックス書籍検索APIを使い、Wikipediaは呼びません。

GUIでは「次巻発売日を確認」ボタンから実行できます（進捗・ログ・中断ボタンは完結チェックと共通です。中断しても、そこまでの結果は保存します）。コマンドラインからは次のように実行します。

```bash
python -m comic_checker.next_release path/to/file.xlsx
```

- 必要なキー: アプリIDとアクセスキー（設定方法はセットアップの5を参照）。未設定の場合はその旨を表示して終了します。
- 読み込むExcelには連載中の作品だけが載っている前提です。連載状況の列では絞り込まず、タイトル列の全行（タイトルが空の行を除く）を対象にします。
- オプション: `--sheet`（対象シート名）・`--header-row`（ヘッダー行番号、既定1）・`--title-column`（タイトル列のヘッダー名、既定「タイトル」）・`--save-every`（保存の間隔、1以上、既定5件）。
- 書き込む列（無ければ末尾に作ります）。既に値がある行も毎回上書きします。
  - 次巻発売日: 次巻の発売日。次巻が見つからないときは状態（下記）を書きます
  - 次巻タイトル: 次巻のタイトル。特装版などがある場合は末尾に「（特装版あり）」を付けます
  - 最新既刊: 発売済みの最新の巻（発売日つき）
  - 発売日参照URL: 発売日の根拠にした商品ページのURL
- 状態の意味:
  - 次巻あり: 次巻の発売日が分かった
  - 未定: 次巻の発売日が決まっていない
  - 要確認: 候補が食い違うなどで自動では決められない（目で確認してください）
  - ヒットなし: 楽天ブックスで該当する作品が見つからなかった
  - エラー: 通信などで調べられなかった

## 動作の仕組み・制限事項

### Wikipedia判定（既定の経路）

- **記事選定**: まずタイトルに「(漫画)」を付けた曖昧さ回避先の記事があればそれを、
  無ければ検索結果の中から「(漫画)」を含むタイトルを優先し、無ければ最上位ヒットを
  採用します。ボット対策のないMediaWiki APIを直接叩くだけなので、ブラウザもAPI
  キーも不要です。
- **完結/連載判定**: 記事のリード文（冒頭）を文単位で見て、「〜連載中」（現在形）と
  「〜まで連載された」「〜をもって完結した」（過去形）を区別して判定します。
- **メディアミックス作品への対応**: リード文に「小説」「ライトノベル」が含まれる
  場合（原作小説とコミカライズが併存する可能性がある場合）、判定文の中に「漫画」
  「コミカライズ」等の語があるものだけを漫画の状態として採用します。原作小説側の
  文しか見つからない、あるいはどちらの主語か判別できない場合は無理に確定させず
  「判定不能」として記録します（例: 原作ライトノベルは完結済みでもコミカライズは
  連載中、というケースの誤判定を防ぐため）。
- **記事が見つからない場合**: 「記事なし」として記録します。

### manba.co.jpフォールバック（`--fallback-to-manba` 指定時のみ）

- Wikipediaで「判定不能」「記事なし」だった行だけ、manba.co.jpの検索ボックスと
  同じ公開検索API（Meilisearch）およびPlaywright経由の作品ページ取得にフォール
  バックします。フォールバックが1件でも発生すると、実行開始時ではなく**最初に
  フォールバックが必要になった時点で**ブラウザを起動し、以降の該当行では同じ
  ブラウザセッションを使い回します。
- manba.co.jpはCloudflareのボット対策下にあるため、連続アクセスするとチャレンジ
  ページが再表示されることがあり、リクエストごとにランダムな待機（デフォルト
  3〜6秒）を入れています。作品ページ取得中にチャレンジページに当たった場合は
  最大3回までリトライ（8秒→16秒→24秒の間隔）し、それでも突破できない場合は
  「不明」として記録し、次のタイトルへ処理を続けます。
- **チャレンジ突破失敗**: フォールバック用ブラウザの起動時にCloudflareチャレンジを
  自動突破できなかった場合は、`RuntimeError`を送出して処理を中断します。特に
  「Verify you are human」のようなチェックボックスをクリックする**インタラクティブ
  なチャレンジ**は、`Just a moment...`型と違って待っても自動では解決しません
  （このチャレンジ自体は自動操作を検知して出ている可能性が高く、`--no-headless`
  で手動クリックの猶予を与えても再発することが確認されています。詳しくは
  [docs/known_limitations.md](docs/known_limitations.md)を参照してください）。
- **セッション再利用**: `.manba_state.json`（gitignore対象、`--state-file`で変更可）
  にPlaywrightのbrowser contextの状態（Cloudflare通過後のCookie等）を保存し、
  次回実行時に再利用します。

### 次巻発売日の確認（楽天ブックス）

- **検索**: Excelのタイトルから注記（括弧書きなど）を除いた名前で、コミックを発売日の新しい順に最大30件取得します。呼び出しの間隔は1秒以上空けます。
- **商品の選び方**: 商品名が作品名で始まり、その後ろが巻数で始まるものを候補にします。画集・ファンブック・小説版などの関連書籍は除きます。
- **次巻の決め方**: 発売前（予約受付中、または発売日が今日より後）の巻のうち最も小さい巻を次巻、発売済みの最も大きい巻を最新既刊とします。発売前の巻が無ければ「未定」です。
- **特装版**: 同じ巻に通常版と特装版・限定版などがあれば通常版を採り、「次巻タイトル」の末尾に「（特装版あり）」を付けます。特装版しか無ければ特装版を採ります。
- **確信がないとき**: 同じ巻で発売日や著者が食い違う、巻数が読み取れない、発売済みかどうか決められない、などのときは無理に確定させず「要確認」にします。
- **既知の制限**: Excelのタイトルと楽天の商品名の表記が違う作品（カタカナと英字など）は「ヒットなし」になります。結果は目視で確かめてください。

### 共通

- **エラー処理**: 1件ごとの処理は`main.py`内でtry/exceptしており、途中で例外が
  発生してもそのタイトルを「エラー」として記録し、処理全体は止めずに次のタイトルへ
  進みます。また `--save-every` 件ごとにExcelを保存するため、途中で処理が
  停止しても、そこまでの結果は保存されています。

## テスト

ネットワークに依存しない形でユニットテストを用意しています
（`excel_io.py`、`wikipedia_client.py`の判定ロジック、`manba_client.py`、
`rakuten_books_client.py`は、それぞれモックで外部通信を差し替えています。
テストは開発機の実際のキーの設定ファイルを読みません）。

```bash
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest
```
